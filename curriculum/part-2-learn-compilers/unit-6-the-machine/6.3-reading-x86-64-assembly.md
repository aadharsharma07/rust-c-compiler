# Lesson 6.3 — Reading x86-64 Assembly
**Part:** 2 — Learn Compilers · **Unit:** 6 — The Machine · **Type:** Learning · **Est. time:** 5–7 h · **Tests:** none
**Prerequisites:** lessons 6.1, 6.2

## Overview
`rcc` will write x86-64 assembly, so you must be able to read it fluently. This lesson moves from
the toy CPU of 6.2 to the real thing: x86-64's registers and their sub-register names, AT&T
syntax, memory operands, and the core instructions (`mov`, `add`, `sub`, `imul`, `neg`, `cmp`,
`jmp`, conditional jumps, `push`, `pop`, `call`, `ret`). You'll read real `clang` output line by
line, use Godbolt, and set up your Apple Silicon Mac to build and run x86-64 programs, then write
and run a few lines of assembly yourself.

## The lesson

### Registers
x86-64 has 16 general-purpose 64-bit registers. Their names are historical (from 16-bit Intel
chips) and each can be accessed at several widths, by different names, all referring to the
*low* part of the same register:

| 64-bit | low 32 | low 16 | low 8 | Main job (lesson 6.4 explains the conventions) |
|---|---|---|---|---|
| `rax` | `eax` | `ax` | `al` | return value; scratch |
| `rbx` | `ebx` | `bx` | `bl` | callee-saved |
| `rcx` | `ecx` | `cx` | `cl` | 4th argument |
| `rdx` | `edx` | `dx` | `dl` | 3rd argument; division |
| `rsi` | `esi` | `si` | `sil` | 2nd argument |
| `rdi` | `edi` | `di` | `dil` | 1st argument |
| `rbp` | `ebp` | `bp` | `bpl` | frame (base) pointer |
| `rsp` | `esp` | `sp` | `spl` | **stack pointer** |
| `r8`–`r15` | `r8d`–`r15d` | `r8w`–`r15w` | `r8b`–`r15b` | `r8`, `r9`: 5th/6th arguments |

```
 bit 63                                 31              15       7       0
  +---------------------------------------+---------------+-------+-------+
  |                          rax (64 bits)                                |
  +---------------------------------------+-------------------------------+
                                          |          eax (32 bits)        |
                                          +---------------+---------------+
                                                          |   ax (16)     |
                                                          +-------+-------+
                                                                  |al (8) |
```

Since a C `int` is 32 bits, most of what you'll write at first uses the 32-bit names (`eax`,
`edi`, ...). One rule to memorise: **writing a 32-bit register zeroes the upper 32 bits** of the
64-bit register (writing `eax` clears the top half of `rax`). Writing 8- or 16-bit names leaves
the other bits alone. Also: `rip` is the instruction pointer, and a separate `RFLAGS` register
holds ZF, SF, CF and OF from 6.2.

### AT&T syntax
There are two ways to write x86-64 assembly. `gcc`, `clang` and the test suite use **AT&T
syntax**, and so will `rcc`. Its rules:

- **Operand order is `source, destination`.** `movl $2, %eax` means "copy 2 into eax".
- **Registers** start with `%`: `%eax`. **Immediates** (constants) start with `$`: `$2`.
- **The mnemonic has a size suffix:** `b` (8), `w` (16), `l` (32), `q` (64). `movl` moves 32
  bits, `movq` moves 64. (The suffix must match the register: `movl %eax, ...`, `movq %rax, ...`.)
- **Comments** start with `#` (clang's output uses `##` too).

The other style, **Intel syntax**, used in Intel's manuals and much online material, reverses the
operands and drops the sigils: `mov eax, 2`. When reading anything online, check which one it is.

### Memory operands
A memory operand means "the value stored in memory at this address". The general form is
`displacement(base, index, scale)`, meaning address = `base + index × scale + displacement`:

| Operand | Address | Typical use |
|---|---|---|
| `-4(%rbp)` | `rbp − 4` | a local variable in the stack frame (6.4) |
| `(%rax)` | `rax` | dereferencing a pointer (Unit 12) |
| `16(%rbp)` | `rbp + 16` | a stack argument (6.4) |
| `8(%rax,%rcx,4)` | `rax + rcx×4 + 8` | an array element (Unit 12) |

Parentheses *always* mean a memory access. `movl -4(%rbp), %eax` loads 4 bytes from address
`rbp − 4` into `eax`; `movl %eax, -4(%rbp)` stores them back. In Python terms, if memory were a
`bytearray` called `mem`, `-4(%rbp)` is roughly `mem[rbp-4 : rbp]` read as a 32-bit integer.

### Core instructions
| Instruction (AT&T) | Effect | Notes |
|---|---|---|
| `movl src, dst` | dst = src | doesn't change flags |
| `addl src, dst` | dst = dst + src | sets flags |
| `subl src, dst` | dst = dst − src | careful: subtracts *source from destination* |
| `imull src, dst` | dst = dst × src | signed multiply; **dst must be a register** |
| `negl dst` | dst = −dst | two's complement negation (6.1) |
| `notl dst` | dst = ~dst | bitwise NOT |
| `cmpl a, b` | compute b − a, set flags, discard | just like the toy `CMP`, *but reversed* |
| `jmp L` | go to label L | |
| `je/jne/jl/jle/jg/jge L` | go to L if equal / not equal / less / ... | read flags from the last `cmp` |
| `pushq src` | rsp −= 8; store src at (rsp) | (6.4) |
| `popq dst` | load (rsp) into dst; rsp += 8 | (6.4) |
| `call f` | push return address; jump to f | (6.4) |
| `ret` | pop return address; jump to it | (6.4) |

Two traps deserve attention:

1. **`cmp` order.** `cmpl %esi, %edi` computes `edi − esi`, so the following `jl L` jumps when
   `edi < esi`. Read `cmp a, b` + `jl` as "jump if **b < a**". Getting this backwards is the most
   common bug in comparison codegen.
2. **At most one memory operand.** `movl -4(%rbp), -8(%rbp)` is *illegal*: x86-64 can't move
   memory to memory. You go through a register: `movl -4(%rbp), %eax` then `movl %eax, -8(%rbp)`.
   Similarly `imull` needs a register destination. Your compiler will need a "fix-up" pass for
   exactly these cases (lesson 9.3).

The jump conditions `jl`, `jle`, `jg`, `jge` are for *signed* comparisons. Unsigned ones use `jb`
("below"), `jbe`, `ja` ("above"), `jae` (Unit 12). There's also a `set` family (`sete`, `setl`,
...) that writes 1 or 0 into an 8-bit register based on the flags; you'll use it in lesson 9.6 to
turn `a < b` into a value.

### Labels and directives
An assembly file also contains:
- **Labels** like `_main:` or `LBB0_1:`, which name the address of the next instruction. Jumps and
  calls target labels; the assembler works out the actual addresses.
- **Directives**, starting with `.`, which instruct the assembler rather than the CPU.
  `.globl _main` makes the symbol `_main` visible to the linker (6.5), so the startup code can
  find it.

**Platform naming.** On macOS, C names get a leading underscore in assembly (`main` → `_main`).
On Linux they don't, and you should end the file with `.section .note.GNU-stack,"",@progbits` to
tell the linker the stack needn't be executable. The smallest complete program, for macOS:

```
    .globl _main          # export the symbol
_main:                    # main starts here
    movl   $2, %eax       # return value goes in eax
    ret                   # return to the caller (the C startup code)
```

### Reading real compiler output
Compile the 5.4 loop program with `clang -S -O0 -arch x86_64 -fno-asynchronous-unwind-tables
loop.c` (`-S` stops after producing assembly, `-O0` turns off optimisation, the last flag removes
`.cfi` noise). Leaving out a few clang directives and comments:

```c
int main(void) {
    int total = 0;
    int n = 4;
    while (n > 0) {
        total = total + n;
        n = n - 1;
    }
    return total;
}
```

```
_main:
    pushq   %rbp                 # prologue: save caller's frame pointer   (6.4)
    movq    %rsp, %rbp           #   and start our own frame
    movl    $0, -4(%rbp)         # (clang's hidden slot for main's return value)
    movl    $0, -8(%rbp)         # total = 0          total lives at rbp-8
    movl    $4, -12(%rbp)        # n = 4              n lives at rbp-12
LBB0_1:                          # loop top
    cmpl    $0, -12(%rbp)        # compute n - 0, set flags
    jle     LBB0_3               # if n <= 0, leave the loop
    movl    -8(%rbp), %eax       # eax = total
    addl    -12(%rbp), %eax      # eax = total + n
    movl    %eax, -8(%rbp)       # total = eax
    movl    -12(%rbp), %eax      # eax = n
    subl    $1, %eax             # eax = n - 1
    movl    %eax, -12(%rbp)      # n = eax
    jmp     LBB0_1               # back to the test
LBB0_3:
    movl    -8(%rbp), %eax       # return value = total
    popq    %rbp                 # epilogue: restore caller's frame pointer
    retq                         # return (clang prints `retq`; `ret` is the same)
```

This is the toy program from 6.2 and the TAC from 5.5 again: a label, `cmp` + `jle` out, a body,
`jmp` back. At `-O0` every variable lives in a memory slot on the stack and is loaded into `eax`
to be worked on; that's exactly the simple strategy `rcc` will use in Units 8–11. Compiling with
`-O2` instead makes clang compute the answer at compile time: the whole function becomes
`movl $10, %eax` + `ret` (with a prologue). That's constant folding and loop optimisation, Unit 13.

### Godbolt
Compiler Explorer (https://godbolt.org) shows source and assembly side by side, with matching
colours for each source line. Choose language **C**, a compiler such as **x86-64 clang** or
**x86-64 gcc**, and options like `-O0`. The output is AT&T syntax by default and uses Linux naming
(no underscore). It hides most directives for you, which makes it the fastest way to answer "what
does a real compiler do with this?"

### Running x86-64 on Apple Silicon
Your Mac's CPU is arm64, not x86-64, so an x86-64 program can't run on it natively. Two options:

**Option A: Rosetta 2 (recommended to start).** Rosetta translates x86-64 programs to arm64 on
the fly.
1. Install it once: `softwareupdate --install-rosetta --agree-to-license`.
2. Build for x86-64 by passing `-arch x86_64` to clang: `clang -arch x86_64 prog.c -o prog`, or
   from your own assembly, `clang -arch x86_64 prog.s -o prog`.
3. Run it: `arch -x86_64 ./prog; echo $?`. (Rosetta usually kicks in automatically for an x86-64
   binary, but `arch -x86_64` makes it explicit.) `file prog` should report
   `Mach-O 64-bit executable x86_64`.
4. You can also open a whole x86-64 shell with `arch -x86_64 zsh`; inside it, `uname -m` prints
   `x86_64`. This is useful for the test suite (6.5).

**Option B: Docker.** An emulated x86-64 Linux:
`docker run --rm -it --platform linux/amd64 -v "$PWD":/work -w /work gcc bash`. Inside, use
`gcc` and Linux conventions (no underscore, the GNU-stack line). It's slower but matches Linux
exactly.

Pick one and stick to it; the course text uses Option A and notes Linux differences.

## Build
1. **Set up x86-64.** Do Option A (or B). Compile `return_2.c` from 5.1 for x86-64, run it with
   `arch -x86_64`, and confirm with `file` that it's an x86-64 binary.
2. **Write assembly by hand.** Create `ret42.s` that returns 42 by moving 40 into `eax` and then
   adding 2. Build it with `clang -arch x86_64 ret42.s -o ret42`, run it, and check `echo $?`.
   Then write versions that compute `(5 + 3) * 4` (use `imull`) and `-(10 - 3)` (use `negl`; the
   exit status will be `256 − 7`; explain why).
3. **A loop in assembly.** Hand-write `sum.s` that computes 4 + 3 + 2 + 1 using registers only
   (e.g. `eax` for total, `ecx` for n), a label, `cmpl`, `jle` and `jmp`. Run it; expect 10.
4. **Read clang's output.** Compile the loop program and the program below with
   `clang -S -O0 -arch x86_64 -fno-asynchronous-unwind-tables`, and annotate *every* instruction
   with a comment in your notes, as above. Which variable lives at which offset? Why did clang
   use `jge` for `if (a < b)`?
   ```c
   int main(void) {
       int a = 6;
       int b = 7;
       if (a < b) {
           return a * b;
       }
       return 0;
   }
   ```
5. **`cmp` drill.** For each, say whether the jump is taken, with `eax = 3`, `ecx = 5`:
   `cmpl %ecx, %eax` + `jl` · `cmpl %eax, %ecx` + `jl` · `cmpl $3, %eax` + `je` ·
   `cmpl $5, %eax` + `jge`.
6. **Spot the illegal instruction(s)**, and fix each with a register: `movl -4(%rbp), -8(%rbp)` ·
   `imull $3, -4(%rbp)` · `addl %eax, $5` · `movq %eax, %rbx`.
7. **Godbolt.** Paste the loop program into Godbolt with x86-64 clang. Compare `-O0`, `-O1` and
   `-O2`. Then switch the compiler to x86-64 gcc at `-O0` and note two differences from clang.

## Check your understanding
1. What's the relationship between `rax`, `eax` and `al`? What happens to the top half of `rax`
   when you write `eax`?
2. In AT&T syntax, which operand of `subl %ecx, %eax` is changed, and to what?
3. After `cmpl %esi, %edi`, under what condition does `jg` jump?
4. Why can't you write `movl -4(%rbp), -8(%rbp)`, and how does a compiler work around it?
5. Why does clang at `-O0` keep loading variables from memory into `eax` and storing them back?
6. Why do macOS assembly files say `_main` while Godbolt shows `main`?

## Common pitfalls
- Reading AT&T operands in Intel order (or following an Intel-syntax tutorial by mistake).
- Getting `cmp` backwards: `cmp a, b` sets flags for `b − a`.
- Mismatched sizes, such as `movl` with a 64-bit register or `movq` with `eax`.
- Forgetting `$` on a constant: `movl 2, %eax` loads from *memory address 2* and crashes.
- On Apple Silicon, forgetting `-arch x86_64`, which silently builds an arm64 program instead.
