# Lesson 0.1 — What a Compiler Is
**Unit:** 0 — Rust Foundations · **Type:** Learning only · **Est. time:** 2–3 h · **Tests:** none
**Prerequisites:** none (some prior programming experience in any language)

## Learning goals
- Describe the phases of a compiler (lex, parse, semantic analysis, IR generation, optimisation, code generation, emission) and what data flows between them.
- Distinguish the *compiler* from the rest of the toolchain: preprocessor, assembler, linker.
- Install Rust with `rustup` and use `cargo new`, `cargo run`, `cargo test`, `cargo fmt` and `cargo clippy`.
- Write and run a unit test with `#[test]` and `assert_eq!`.

## Key ideas
**A compiler translates a program from one language into another**, usually from a high-level
language into assembly or machine code. It is a pipeline of passes; each pass consumes one
representation and produces the next, so each can be understood and tested on its own.

| Phase | Input → Output | Question it answers |
|---|---|---|
| Lexer | characters → tokens | "What are the words?" |
| Parser | tokens → AST | "How do the words group together?" |
| Semantic analysis | AST → checked AST | "Does this make sense (names, types)?" |
| IR generation | AST → flat IR (TACKY, later) | "What are the simple steps?" |
| Optimisation | IR → better IR | "Can we do less work?" |
| Code generation | IR → assembly AST | "Which machine instructions?" |
| Emission | assembly AST → `.s` text | "How does the assembler want it spelled?" |

**Worked example.** For `int main(void) { return 2; }`:
- Tokens: `int` `main` `(` `void` `)` `{` `return` `2` `;` `}`
- AST (sketch): `Program(Function(name="main", body=Return(Constant(2))))`
- x86-64 assembly, AT&T syntax, as `clang -S -O2` produces on macOS (directives trimmed):

```
    .globl _main
_main:
    movl    $2, %eax
    ret
```
On Linux the symbol is `main` with no underscore: macOS prefixes C symbols with `_`.
AT&T syntax puts the **source first, destination second** and marks immediates with `$`
and registers with `%`. The return value of `main` travels in `%eax`.

**The driver.** `gcc`/`clang` is really a *driver*: it runs the preprocessor (`-E`),
the compiler proper (`-S` → `.s`), the assembler (`-c` → `.o`) and the linker (→ executable).
Your `rcc` will do only the middle step and call the system tools for the rest.

**Apple Silicon note.** The test suite expects x86-64. On an M-series Mac, `clang -arch x86_64`
builds x86-64 code and `arch -x86_64 ./prog` runs it under Rosetta 2; alternatively use an
x86-64 Linux Docker container. Set this up now rather than in Unit 1.

**Cargo** is Rust's build tool and package manager. A crate has `Cargo.toml` (metadata,
dependencies) and `src/main.rs` (binary) or `src/lib.rs` (library). `cargo test` compiles
and runs every function marked `#[test]`; `cargo clippy` runs extra lints.

## Questions the tutor should ask you
1. Why split a compiler into many small passes instead of one big function from text to assembly?
2. What would go wrong if the lexer tried to decide whether `x` was a declared variable?
3. In `movl $2, %eax`, which operand is written to? How do you know?
4. What's the difference between what `clang -S` and `clang -c` produce?
5. If tests are free to run, why might a compiler author still keep each test tiny?

## What you build
Learning only. Exercises:
1. Install Rust with `rustup` (see the Book, ch. 1). Check `rustc --version`, `cargo --version`,
   `cargo clippy --version`. Install `rustfmt`/`clippy` components if missing.
2. `cargo new fizzbuzz`. Write a function that maps a number to `"Fizz"`, `"Buzz"`, `"FizzBuzz"`
   or the number as a string, and a `main` that prints 1–100. Write at least four `#[test]`
   functions covering each case, including 15 and 1. Make `cargo clippy` silent.
3. Write `return2.c` (`int main(void) { return 2; }`). Run `clang -S -O0 return2.c` and, on
   Apple Silicon, also `clang -S -arch x86_64 -O0 return2.c`. Open both `.s` files and annotate
   every line in comments: directive, label, or instruction, and what it does. Guess what you
   don't know, then check.
4. Repeat with `-O2`. Which lines disappeared, and why might the compiler be allowed to drop them?
5. Build and run the binary; check the exit status with `echo $?` (expect `2`). On Apple Silicon,
   build x86-64 and run it with `arch -x86_64 ./a.out`.
6. Paste `return2.c` into Godbolt (compiler explorer), choose x86-64 clang, and compare with your file.
7. Start Rustlings (`00_intro`, `01_variables`, `02_functions`, `03_if`) to warm up syntax.

## Common pitfalls
- Reading AT&T operands Intel-style (destination first). AT&T is `op src, dst`.
- Forgetting the `_` prefix on macOS, or expecting it on Linux.
- Building an arm64 binary on Apple Silicon without noticing; check with `file a.out`.
- Ignoring clippy warnings now; they are cheap lessons in idiomatic Rust.
- Testing only the "happy" values; pick boundary cases (1, 3, 5, 15).
