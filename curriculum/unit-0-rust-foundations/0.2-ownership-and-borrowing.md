# Lesson 0.2 — Ownership & Borrowing
**Unit:** 0 — Rust Foundations · **Type:** Learning only · **Est. time:** 4–6 h · **Tests:** none
**Prerequisites:** lesson 0.1

## Learning goals
- State Rust's three ownership rules and predict when a value is *moved*, *copied* or *dropped*.
- Use shared (`&T`) and mutable (`&mut T`) references and explain the "many readers XOR one writer" rule.
- Choose between `String` (owned, growable) and `&str` (borrowed view) for function parameters and struct fields.
- Relate ownership to compiler design: a lexer *borrows* the source text; tokens and AST nodes *own* their data (or borrow it, with care).

## Key ideas
**Ownership rules.** Every value has exactly one owner; when the owner goes out of scope the
value is dropped; ownership can be transferred (*moved*). Assigning or passing a `String`
moves it: the old binding becomes unusable. Types that are cheap bitwise copies (`i32`, `bool`,
`char`, `&T`) implement `Copy` and are copied instead of moved.

**Borrowing.** A reference lets you use a value without taking ownership.
- Any number of `&T` at once, **or** exactly one `&mut T`, never both.
- A reference must never outlive the value it points to (no dangling pointers).
- The borrow checker reasons about where each reference is last *used*, not just where its scope ends.

**`String` vs. `&str`.** `String` owns a heap buffer of UTF-8 bytes. `&str` is a pointer + length
into some UTF-8 bytes owned by someone else (a `String`, or the binary for a literal). Taking
`&str` as a parameter accepts both: `&my_string` coerces to `&str`.

**Worked example: what does a lexer hold?** Source: `"12 + x"` (one `String` read from a file).
- The lexer only needs to *read* it, so it holds a `&str` (or an iterator of `char`s) borrowing the source.
- A token for `12` could store the number `12` (owned, `Copy`), and a token for `x` could store an
  owned `String` `"x"` (simple; costs an allocation) or a `&str` slice `"x"` pointing into the source
  (cheap; ties the token's lifetime to the source). You will meet that trade-off again in Unit 1.

**Indices vs. chars.** Slicing a `&str` uses *byte* indices; `s.chars()` yields Unicode scalar
values. For ASCII-only C source they coincide, but slicing mid-character panics.

**Isolated illustration** (unrelated to the calculator):
```rust
let a = String::from("hi");
let b = a;            // a moved into b; using `a` now is error E0382
let n = b.len();      // fine: len borrows b
```

## Questions the tutor should ask you
1. Before running it: does `let b = a;` compile if `a` is an `i32`? If `a` is a `String`? Why the difference?
2. A function only prints a name. Should it take `String`, `&String` or `&str`? Why?
3. Why can't you hold a `&v[0]` while calling `v.push(...)`?
4. If a token stores a `&str` slice of the source, what must be true about the source `String`?
5. When would you deliberately call `.clone()`, and what does it cost?

## What you build
Learning only. In a scratch crate `cargo new ownership-lab`:
1. **Predict, then compile.** Write five tiny snippets that you *expect* to fail (use after move,
   two `&mut` at once, `&` and `&mut` overlapping, returning a reference to a local, pushing while
   borrowing). For each, write your prediction as a comment, compile, then read the full `rustc`
   error and explain it in your own words to the tutor. Use `rustc --explain E0382` etc.
2. **`first_word(&str) -> &str`**: return the text up to the first space. Test with `""`,
   `"one"`, `"two words"`, `"  leading"`.
3. **`count_digits(&str) -> usize`** and **`shout(&mut String)`** (appends `"!"`). Test both.
4. **`split_numbers(&str) -> Vec<i64>`**: given `"3 14 15"`, return `[3, 14, 15]`; decide and test
   what happens with `"3 x 4"` (skip? stop? panic?). Write down why you chose it; next lesson
   you will redo it with `Result`.
5. Rustlings: `05_vecs`, `06_move_semantics`, `09_strings`.

## Common pitfalls
- Sprinkling `.clone()` to silence the borrow checker without understanding the error.
- Taking `&String` or `String` parameters where `&str` would do.
- Slicing strings with byte indices from `chars().enumerate()` (char positions ≠ byte offsets for non-ASCII).
- Assuming a borrow lasts to the end of the block; modern Rust ends it at the last use.
- Fighting lifetimes by storing references in structs too early; owned data is fine while learning.
