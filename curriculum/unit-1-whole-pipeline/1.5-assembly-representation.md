# Lesson 1.5 — Assembly Representation
**Unit:** 1 — The Whole Pipeline for `return 2;` · **Type:** Builds assembly AST + AST→asm pass · **Est. time:** 2–3 h · **Tests:** ch. 1 (`--stage codegen`)
**Prerequisites:** lessons 1.1, 1.4

## Learning goals
- Explain why compilers lower through several intermediate representations instead of printing assembly straight from the AST.
- Design a small, typed representation of x86-64 assembly (programs, functions, instructions, operands).
- Write a pass that walks one tree and builds another, using exhaustive `match`.
- Keep "what to compute" (code generation) separate from "how to spell it" (emission).

## Key ideas
**Why not print text directly from the AST?** It works for `return 2;`, but it breaks down fast.
Later passes need to *inspect and rewrite* instructions: replace pseudoregisters with stack slots,
fix illegal operand combinations, allocate registers. Those are tree transformations, and they are
easy on data and miserable on strings. A typed assembly AST also lets the Rust compiler stop you
from building nonsense (like an instruction with three operands where two are required).

**Levels of representation in this course:**
```
C source → tokens → C AST → (Unit 2: TACKY IR) → assembly AST → assembly text
```
Each level is closer to the machine. The assembly AST is a one-to-one model of the instructions
you will emit, but it is still structured data.

**The chapter-1 assembly AST** (ASDL-like notation):
```
program             = Program(function_definition)
function_definition = Function(identifier name, instruction* instructions)
instruction         = Mov(operand src, operand dst) | Ret
operand             = Imm(int) | Register
```
`Register` has no data yet because the only register you need is `%eax`; in Unit 2 it becomes an
enum of specific registers. `instruction*` means "a list of instructions".

**Lowering rules for chapter 1:**

| C AST | Assembly AST |
|---|---|
| `Program(f)` | `Program(lower(f))` |
| `Function(name, body)` | `Function(name, lower(body))` |
| `Return(exp)` | `Mov(lower(exp), Register)`, `Ret` |
| `Constant(n)` | `Imm(n)` |

**Worked example.** `Program(Function("main", Return(Constant(2))))` lowers to
```
Program(Function(name = "main",
    instructions = [ Mov(Imm(2), Register), Ret ]))
```
which lesson 1.6 will print as `movl $2, %eax` / `ret`.

Note that one statement became *two* instructions: lowering is one-to-many, which is why a
statement lowers to a list (or appends to one).

## Questions the tutor should ask you
- What later transformation would be painful if your code generator produced strings?
- Why does `Return` produce two instructions? Which one carries the value and which transfers control?
- Should the lowering functions take the AST by value or by reference? What changes if you consume it?
- Where will platform differences (macOS `_main`) be handled: here or in emission? Why?
- How would you add a second register to the `operand` type without breaking existing code?

## What you build
- An `asm` (or `assembly`) module with types for program, function, instruction and operand as
  above. Instructions and operands are enums; function and program are structs.
- A `codegen` module with a public entry point: C AST `Program` in, assembly `Program` out. It
  cannot fail for now (all checking happened in the parser), so it need not return a `Result`.
- **Driver:** `--codegen` runs lex → parse → codegen and stops, writing no files, exit 0.
- **Unit test:** lowering the worked example's AST produces exactly the instruction list above.
- Keep the function name as data; do **not** add the `_` prefix here.

## Common pitfalls
- Naming collisions: your C AST and assembly AST both have `Program` and `Function`. Use modules
  (`ast::Program` vs. `asm::Program`) rather than awkward names.
- Using a wildcard `_ =>` arm in a `match` over AST nodes: you lose the compiler's help when variants are added in Unit 2.
- Putting the `_` prefix or `%eax` spelling in the assembly AST instead of the emitter.
- Over-designing (all 16 registers, every instruction) before you need it.
