# Lesson 1.6 — Code Emission
**Unit:** 1 — The Whole Pipeline for `return 2;` · **Type:** Builds emitter → first executable · **Est. time:** 2–4 h · **Tests:** ch. 1
**Prerequisites:** lessons 1.2, 1.5

## Learning goals
- Print an assembly AST as AT&T-syntax text that `gcc`/`clang` will assemble.
- Handle platform differences: the macOS `_` symbol prefix and the Linux `.note.GNU-stack` section.
- Use `std::fmt::Write` (or `Display`) to build text without allocating a `String` per fragment.
- Connect every stage into a driver that produces a real executable and passes chapter 1.

## Key ideas
**Emission is mechanical.** Every assembly-AST node has exactly one textual form:

| Node | Text |
|---|---|
| `Program(f)` | the function, then (Linux only) `.section .note.GNU-stack,"",@progbits` |
| `Function(name, instrs)` | `.globl <sym>`, then `<sym>:`, then each instruction |
| `Mov(src, dst)` | `movl <src>, <dst>` |
| `Ret` | `ret` |
| `Register` | `%eax` |
| `Imm(n)` | `$n` |

where `<sym>` is `_main` on macOS and `main` on Linux.

Convention: labels start in column 0; directives and instructions are indented with a tab; a
tab between mnemonic and operands keeps the output readable. Every line ends with a newline,
including the last (some assemblers warn otherwise).

**Worked example.** `Program(Function("main", [Mov(Imm(2), Register), Ret]))` emits, on macOS:
```
	.globl _main
_main:
	movl	$2, %eax
	ret
```
and on Linux:
```
	.globl main
main:
	movl	$2, %eax
	ret
	.section .note.GNU-stack,"",@progbits
```

**Why the `_`?** Mach-O (macOS) prefixes every C symbol with an underscore at the assembly level;
the C runtime calls `_main`. ELF (Linux) doesn't. **Why the section?** Without it, GNU `ld`
assumes the object might need an executable stack and warns (and on some systems marks the stack
executable). Decide the platform at compile time of `rcc` (`cfg!(target_os = "macos")`) or at run
time (`std::env::consts::OS`); either way the emitter, and only the emitter, knows about it.

**Text building in Rust.** `std::fmt::Write` lets `write!`/`writeln!` append to a `String`;
`std::io::Write` writes to files and streams. Implementing `Display` for operands lets you write
`{}` for an operand anywhere. Building the whole `.s` in a `String` and then writing it once is
simple and fast enough.

## Questions the tutor should ask you
- Which parts of the output depend on the platform, and where in your code is that decision made?
- What's the difference between `fmt::Write` and `io::Write`? Which one does `String` implement?
- What happens when `writeln!` into a `String` "fails"? Why does it return a `Result` at all?
- If `gcc` rejects your `.s`, how will you debug it? (Hint: `-S`.)
- How would you check that the executable really returns 2, by hand?

## What you build
- An `emit` module: assembly `Program` in, assembly text (`String`) out.
- `Display` impls (or private helper functions) for operands and instructions, producing exactly
  the spellings in the table above.
- Platform handling for the symbol prefix and the GNU-stack note, in one place.
- **Driver:** replace the 1.2 stub. A full compile now runs lex → parse → codegen → emit, writes
  `prog.s`, assembles and links with `gcc` (adding `-arch x86_64` on macOS), and deletes `prog.s`.
  `-S` keeps `prog.s` and skips linking.
- **Unit test:** emitting the worked example's assembly AST yields exactly the expected text for the
  platform you're on.
- Run the full chapter: valid programs produce executables with the right exit codes, invalid
  programs fail at lexing or parsing.

Importing the trait is what makes the method available: `use std::fmt::Write;` must be in scope
before `writeln!(s, "ret")` works on a `String` `s`.

## Common pitfalls
- `use std::fmt::Write` and `use std::io::Write` both in one module: name clash; alias one (`as _`).
- Emitting `movl 2, %eax` (missing `$`): that is a load from memory address 2, which segfaults.
- Getting the symbol prefix wrong, or applying it to labels that aren't C symbols (relevant in Unit 2).
- Forgetting the trailing newline, or leaving the `.s` behind after a successful full compile.
- Hard-coding the platform in emitted text and then running inside Docker (Linux) and wondering why linking fails.
