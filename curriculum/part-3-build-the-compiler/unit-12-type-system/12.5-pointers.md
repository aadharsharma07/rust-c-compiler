# Lesson 12.5 — Pointers
**Part:** 3 — Build the Compiler · **Unit:** 12 — A Real Type System · **Type:** Builds `&`, `*` · **Est. time:** 10–14 h · **Tests:** ch. 14
**Prerequisites:** lessons 12.1–12.4; 2.1 and 2.3 (stack, heap and references in Rust); 6.3 (memory operands)

## Overview
Pointers are the feature that makes C feel low-level: a value that *is* a memory address, which you can store, pass
around and read or write through. This lesson explains what that means from a Python point of view, then teaches you to
parse C's inside-out declaration syntax, to distinguish "a place" from "a value" (lvalues), and to generate loads and
stores through addresses. Arrays (12.6), strings (12.7), `malloc` (12.8) and structs (12.9) are all built on top of this.

## The lesson

### What a pointer is, seen from Python
In Python every variable already holds a reference to an object, but you can never see or do arithmetic on the address.
(CPython's `id(x)` happens to be the address, and that is as close as you get.) Two names can refer to one list, so
changing it through one name is visible through the other. That is pointer behaviour, hidden.

C makes it explicit. Every variable lives at some address in memory. `&x` ("address of x") produces that address as a
value, and its type is "pointer to the type of x". `*p` ("dereference p") means "the object at the address in p":

```c
int x = 3;
int *p = &x;    /* p's type is int * ("pointer to int"); its value is x's address */
*p = 7;         /* write 7 into the object p points at: x is now 7 */
int y = *p;     /* read through p: y is 7 */
```

Memory afterwards (addresses are made up; a pointer is 8 bytes on x86-64):

```
 address   contents          name
 0x1000    7                 x   (int, 4 bytes)
 0x1008    0x1000            p   (int *, 8 bytes): "points at x"
 0x1010    7                 y
```

Python's `ctypes` module lets you try this from Python: `p = ctypes.pointer(ctypes.c_int(3)); p.contents.value = 7`.
Rust references (`&x`, `*r`, from 2.3) are the same machine idea, with the borrow checker guaranteeing they are valid.
C has no such guarantee: dereferencing a pointer to something that no longer exists is undefined behaviour.

Pointers can point to pointers: `int **pp = &p;` then `**pp` is `x`. A pointer is a *scalar*: you can test it for truth
(`if (p)`), and the special **null pointer** (written `0` in C source) means "points at nothing", like Python's `None`.

### Declarators: C types are written inside out
In `int *p, x;`, the `*` belongs to `p`, not to `int`: `p` is a pointer and `x` is a plain `int`. A declaration is a
**base type** (`int`) plus a **declarator** for each name, which wraps the base type. Read a declarator by asking "what
must I do to the name to get the base type?". `*p` is an `int`, so `p` is a pointer to `int`.

Parse the declarator into a small tree with three kinds of node: an identifier, pointer-to (`*D`), and
function-with-parameters (`D(params)`). Then process it from the outside in:
- `*D` with base type T: process `D` with base type `Pointer(T)`.
- `D(params)` with base type T: `D` is a function returning T.
- identifier: the name gets the accumulated type.

Postfix `(params)` binds tighter than prefix `*`, and parentheses override that. So `int *f(void)` is a function
returning `int *`, while `int (*p)` is just a pointer to `int` (the parentheses matter later: `int (*a)[3]` in 12.6).
Casts use **abstract declarators** that have no name: `(int **) x`. Function pointers like `int (*f)(void)` are out of scope.

### Lvalues and lvalue conversion
An **lvalue** is an expression that designates an object, a *place* in memory: a variable, or `*e` for any pointer `e`.
`x + 1` and `3` are not lvalues; they are just values. When an lvalue is used where a value is needed, C reads the object's
current contents: this is **lvalue conversion**. It does *not* happen in two places: the operand of `&`, and the left side of
`=`. That is why `&x` and `*p = 1` are valid, while `&(x + 1)`, `&3` and `(x + 1) = 1` are errors.

### Places versus values in TACKY
TACKY generation now has to know whether an expression is a place or a value. Let expression lowering return one of two
results: a **plain operand** (a constant or variable), or a **dereferenced pointer** (an operand holding an address that has
not been read yet). The caller decides what to do with it:

| The caller wants… | plain operand | dereferenced pointer `ptr` |
|---|---|---|
| its value | use it as is | `Load(ptr, tmp)`, then use `tmp` |
| to assign to it | `Copy(src, var)` | `Store(src, ptr)` |
| its address | `GetAddress(var, tmp)` | `ptr` itself (so `&*p` is just `p`) |

### Worked example

```c
int main(void) {
    int x = 3;
    int *p = &x;
    *p = 7;
    return x;
}
```

```
x = 3
tmp.0 = GetAddress(x)
p = tmp.0
Store(7, p)
Return(x)
```

```asm
    movl    $3, -4(%rbp)
    leaq    -4(%rbp), %r11        # lea computes an address without reading memory
    movq    %r11, -16(%rbp)       # tmp.0   (lea needs a register destination)
    movq    -16(%rbp), %r10
    movq    %r10, -24(%rbp)       # p = tmp.0
    movq    -24(%rbp), %rax       # Store: load the pointer into a register…
    movl    $7, (%rax)            # …then write through it
    movl    -4(%rbp), %eax        # return x: 7
```

`leaq` ("load effective address") computes `%rbp - 4` and stores the *address*; it never touches memory. `Load(ptr, dst)`
mirrors `Store`: `movq ptr, %rax`, then `movl (%rax), …`. A static variable's address is `leaq x(%rip), %r11`
(`_x(%rip)` on macOS). Replace your stack operand with a general **`Memory(register, offset)`** operand: `-4(%rbp)` is
`Memory(BP, -4)` and `(%rax)` is `Memory(AX, 0)`.

### Type rules for pointers
A pointer is 8 bytes, uses the `Quadword` assembly type, and compares like an unsigned integer (addresses are never
negative), so `<` etc. would use `b`/`a` condition codes when they arrive in 12.6.
- `*e` requires a pointer and has the pointed-to type. `&e` requires an lvalue and has type pointer-to-(type of e).
- A **null pointer constant** is an integer constant with value 0 (`0`, `0L`, `0u`). In this course's subset, an integer
  literal is enough; record your exact rule in your journal.
- Conversion "as if by assignment" to a pointer type is allowed only from the *same* pointer type or a null pointer
  constant. `int *p = 5;` and `long *q = p;` are errors.
- `==` and `!=` need two pointers of the same type, or a pointer and a null constant. The same *common pointer type* rule
  types `c ? p : 0`.
- Explicit casts between pointers and integers are allowed; casts between pointers and `double` are errors.
- Reject `*`, `/`, `%`, unary `-` and `~` on pointers. Pointer `+`, `-`, `<` and `>` come in 12.6.

### Rust notes
A pointer type contains another type, so `Type` needs a `Box` to be finite (Part 1, 4.4). Equality still derives
through the box. Here is the shape on a toy type:

```rust
#[derive(Debug, Clone, PartialEq)]
enum Shape { Dot, Wrapped(Box<Shape>) }
```

The plain-vs-dereferenced result should be an enum, not two `Option`s, so `match` forces every caller to handle both.

## Build
1. **Parser.** Parse declarators and abstract declarators for variables, parameters, function return types and casts.
   Add unary `&` and `*`. Reject function pointers and functions returning functions.
2. **Types.** Add `Pointer(referenced type)`. Reject taking the address of a function.
3. **Type checker.** Lvalue checks for `&` and `=` (and `++`/`--`/compound assignment if you did them); dereference checks;
   the conversion rules above; common pointer type for `==`, `!=`, `?:`. A static pointer may only be initialised with a
   null constant.
4. **TACKY.** `GetAddress`, `Load`, `Store`, and the two-variant expression result.
5. **Assembly.** `Memory(reg, offset)` replaces the stack operand; add `Lea`. `Load`/`Store` go through `%rax`.
   Pointer comparisons use unsigned condition codes.
6. **Fix-ups.** The destination of `lea` must be a register. Never hold the pointer for `Load`/`Store` in `%r10`/`%r11`,
   because another fix-up of the same instruction might overwrite it.
7. **Test these yourself:** `**pp = 1`; `&*p`; a function returning a pointer to a static variable; a pointer to `double`;
   `(int *) 0 == 0`; dereferencing in a `return`; pointer arguments past the sixth. Then run `--chapter 14`.

## Common pitfalls
- Treating the `*` in `int *p, q;` as part of the base type, so `q` also becomes a pointer.
- Lvalue-converting the operand of `&`, so you take the address of a temporary copy.
- Lowering `*p = v` as `Load` then `Copy` into a temporary, so memory is never written.
- Using signed condition codes for pointer comparisons.
- Allowing implicit conversion between different pointer types, or from a non-zero integer.
