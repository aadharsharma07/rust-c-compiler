# Lesson 12.9 — Structs

## Overview
A struct groups named values of different types into one value, like a Python dataclass without methods. It is the last
and largest lesson of the unit, because structs touch every pass: a new namespace for struct names, memory layout with
padding, member access, whole-struct copies, and the System V rules for passing structs in registers. When you finish,
your compiler handles every type in this course's subset of C.

## The lesson

### What a struct is, seen from Python
A Python dataclass is an object on the heap; its fields are references in a dictionary-like structure, and assigning it to
another variable shares the same object. A C struct is a block of raw bytes holding each member directly, one after another:

```c
struct point { int x; int y; };    /* declares the type "struct point" */

struct point p = {1, 2};           /* p.x is 1, p.y is 2 */
struct point q = p;                /* copies all 8 bytes: q is independent of p */
struct point *pp = &p;
pp->x = 10;                        /* p->m is shorthand for (*p).m */
```

Two big differences from Python: assigning a struct **copies** it (like assigning an `int`), and passing a struct to a
function passes a copy too. To share one, you pass a pointer. Rust structs (lesson 3.1) work like C's: plain bytes, copied
or moved by value. Python's `ctypes.Structure` models C structs exactly, including their padding:

```python
>>> import ctypes
>>> class S(ctypes.Structure):
...     _fields_ = [("a", ctypes.c_char), ("b", ctypes.c_int)]
>>> ctypes.sizeof(S), S.b.offset
(8, 4)
```

### Tags and their scope
In `struct point { … }`, `point` is a **tag**. Tags live in a separate namespace from variables (a variable may also be
called `point`) and follow block scope, like variables (10.4). As in your variable-resolution pass, give each tag
declaration a unique internal name, so an inner `struct point` that shadows an outer one is a different type.
`struct s;` declares an **incomplete** type (12.8): you can declare pointers to it, but not variables of it, until a later
`struct s { … };` completes it. A struct may contain a pointer to itself (`struct node *next;`, the classic linked list),
but not itself. (In full C, `struct s *p;` with no visible `s` declares one implicitly; check how the suite treats an
unseen tag before you decide.)

### Layout: offsets, padding and alignment
Each member goes at the next offset that is a multiple of **its** alignment. The struct's alignment is its **largest**
member alignment, and its size is rounded up to a multiple of that, so that in an array of structs every element stays
aligned:

```c
struct s { char a; int b; double c; char d; };
```

```
offset: 0    1  2  3  4        8                16   17 ............ 23
       ┌────┬───────┬────────┬────────────────┬────┬────────────────┐
       │ a  │ pad   │   b    │       c        │ d  │      pad       │  size 24, alignment 8
       └────┴───────┴────────┴────────────────┴────┴────────────────┘
```

Array members use their element's alignment; the "16 bytes or more → 16-aligned" rule from 12.6 is for array *variables*
only. Keep a **type table**: for each struct tag, its size, alignment and ordered members (name, type, offset).

### Member access in TACKY
Extend the expression result from 12.5 with a third variant: a **sub-object** (a base variable plus a byte offset).
- `s.m` where `s` is a plain variable → sub-object (`s`, offset of `m`). Reading it is `CopyFromOffset(s, offset, dst)`;
  writing it is `CopyToOffset(src, s, offset)`.
- `s.m` where `s` is a dereferenced pointer, and `p->m` → add the offset to the pointer (`AddPtr` with scale 1, or a
  plain add), giving a dereferenced pointer to the member.
- Nested access `a.b.c` adds the offsets. A whole struct is copied with an ordinary `Copy`; the back end splits it.

`s.m` is an lvalue only if `s` is, so `f().x = 3;` is an error (the call result is a temporary value), while `p->x = 3;` is fine.

### How structs travel in calls: System V classification
Lesson 6.4 covered scalars. For structs, the ABI first **classifies** the struct:
1. Larger than 16 bytes → **MEMORY**: passed on the stack (a copy), never in registers.
2. Otherwise, split it into **eightbytes** (bytes 0–7 and 8–15). An eightbyte whose members are *all* `double` is
   **SSE**; any other eightbyte is **INTEGER**. Nested structs and arrays are flattened into their scalars first.

```c
struct a { int x; int y; };          /* [INTEGER]          → %rdi              */
struct b { double d; int i; };       /* [SSE, INTEGER]     → %xmm0 + %rdi      */
struct c { double x; double y; };    /* [SSE, SSE]         → %xmm0 + %xmm1     */
struct d { char c[17]; };            /* MEMORY             → copied onto stack */
```

**Arguments:** each eightbyte takes the next free register of its class. If there are not enough registers left for
*all* of a struct's eightbytes, the *whole* struct goes on the stack, padded to a multiple of 8 bytes.
**Return values:** INTEGER eightbytes come back in `%rax` then `%rdx`; SSE eightbytes in `%xmm0` then `%xmm1` (so
`[SSE, INTEGER]` returns in `%xmm0` and `%rax`). For a **MEMORY** return, the *caller* reserves space and passes its address
as a hidden first argument in `%rdi`, shifting the visible arguments along by one register. The callee writes the result
there and returns the same address in `%rax`.

### Worked example

```c
struct pair { int a; double b; };    /* size 16, align 8, [INTEGER, SSE] */
double get_b(struct pair p) { return p.b; }
```

```
get_b(p):
    tmp.0 = CopyFromOffset(p, 8)
    Return(tmp.0)
```

```asm
    movq    %rdi, -16(%rbp)       # eightbyte 0: a plus 4 bytes of padding
    movsd   %xmm0, -8(%rbp)       # eightbyte 1: b
    movsd   -8(%rbp), %xmm14
    movsd   %xmm14, -24(%rbp)     # tmp.0 = p.b
    movsd   -24(%rbp), %xmm0      # return the double in %xmm0
```

### Copying without overrunning
A 12-byte struct's second eightbyte holds only 4 bytes. Moving it with `movq` would read or write 4 bytes past the object,
which can corrupt a neighbour or fault at a page boundary. Copy aggregates in 8-, 4- and 1-byte chunks, and when loading a
partial eightbyte into a register, move exactly the right number of bytes (for example, single bytes combined with shifts).

### Rust notes
`Type::Structure` should hold only the tag; the layout lives in a `HashMap` from tag to definition. `usize::next_multiple_of`
expresses "round up to alignment" directly:

```rust
assert_eq!(5_usize.next_multiple_of(4), 8);
```

Classification results (a list of `Integer`/`Sse` eightbytes, or `Memory`) make a good small enum.

## Build

1. **Lexer and parser.** The `struct` keyword and `.`/`->` tokens; struct declarations with or without a member list, at file
   and block scope; struct specifiers in declarations, casts and `sizeof`; postfix `.`/`->`; nested initialisers.
2. **Resolution.** A tag map with block scoping, parallel to the variable map; unique internal names for tags.
3. **Type table and layout.** Size, alignment, ordered members with offsets. Reject duplicate members, members of incomplete
   or `void` type, and redefining a tag in the same scope. Unit-test layout.
4. **Type checker.** `.` needs a complete struct, `->` a pointer to one; unknown members are errors. Struct values may be
   assigned, initialised, passed, returned and used in `?:` only with an *identical* struct type. Reject structs in
   arithmetic, comparisons, truth tests and casts to struct types, and objects of incomplete type.
5. **TACKY.** `CopyFromOffset`; the sub-object result; struct initialisers via `CopyToOffset`; static struct initialisers
   with padding emitted as zero bytes.
6. **Assembly: copies.** Aggregate copies in 8/4/1-byte chunks.
7. **Assembly: classification and calls.** Classify (and cache) each struct; pass and receive arguments of every class;
   return values in registers or through the hidden pointer, saving that pointer on entry. Unit-test classification.
8. **Test these yourself:** structs holding arrays and other structs; arrays of structs; pointers to incomplete structs

## Common pitfalls
- Giving a struct the alignment of its *first* member instead of its *largest*.
- Classifying by member types without first flattening nested structs and arrays into eightbytes.
- Splitting a struct between registers and the stack when registers run out: it must go entirely on the stack.
- Forgetting that the hidden return pointer occupies `%rdi`, so the first visible argument moves to `%rsi`.
- Reading or writing past the end of a struct when copying its last eightbyte.
- Not saving the hidden pointer on entry, then finding `%rdi` clobbered by the time you `return`.
