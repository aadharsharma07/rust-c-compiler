# Lesson 12.7 — Characters and strings
**Part:** 3 — Build the Compiler · **Unit:** 12 — A Real Type System · **Type:** Builds `char`, strings · **Est. time:** 6–8 h · **Tests:** ch. 16
**Prerequisites:** lessons 12.1–12.6; 2.4 (strings and UTF-8 in Rust); 6.1 (sign and zero extension)

## Overview
C has no string type. Its "strings" are arrays of one-byte integers called `char`, ended by a zero byte. This lesson
explains that model from a Python point of view, then adds the three character types, character and string literals
with escape sequences, byte-sized instructions, and string data in read-only memory. At the end your compiled programs
can print text with `puts`.

## The lesson

### What `char` and C strings are, seen from Python
A Python `str` is a sequence of Unicode code points with a stored length. A C "string" is much more primitive:
- `char` is a **1-byte integer**. `'a'` in C is not a string, it is the number 97 (Python's `ord('a')`).
- A string is a **`char` array whose end is marked by a zero byte**, called NUL and written `'\0'`. There is no stored
  length: code finds the end by scanning for the zero.
- `"hi"` is therefore 3 bytes: `'h'`, `'i'`, `'\0'`. Its type is `char[3]`.

The closest Python type is `bytes`: `b"hi\x00"` is exactly the memory of the C literal `"hi"`. C knows nothing about
Unicode; a string is just bytes.

```c
char c = 'a';            /* c holds 97 */
char s[4] = "abc";       /* s holds 'a' 'b' 'c' '\0' */
char *p = "hello";       /* p points at the first byte of a read-only "hello\0" */
int puts(char *s);       /* libc: prints bytes up to the NUL, then a newline */
```

### Three character types
`char`, `signed char` and `unsigned char` are all 1 byte, and they are three **different** types: `char *` and
`signed char *` are incompatible pointer types. `signed char` holds −128 … 127 and `unsigned char` 0 … 255. Whether plain
`char` is signed depends on the platform; on x86-64 System V it is **signed**, so it behaves like `signed char` in
arithmetic and conversions. So `char c = 200;` truncates 200 (`0xC8`) into one byte, and reading `c` gives −56.

### Integer promotions
Lesson 12.3 prepared for this. Before arithmetic, a unary operator, or a comparison, any character-typed operand is first
converted to `int`. In `c + 1` with `char c`, `c` is sign-extended to `int` and the result is `int`; for an
`unsigned char` it is zero-extended. Promotion is why `c1 + c2` never overflows a byte. Character *constants* such as
`'a'` already have type `int` in C.

### Escape sequences and concatenation
Character constants and string literals both understand `\'`, `\"`, `\?`, `\\`, `\a`, `\b`, `\f`, `\n`, `\r`, `\t`, `\v`
(as in Python, `\n` is byte 10). A raw newline inside either is an error, as are an unescaped `'` in a character constant,
an unescaped `"` in a string, an empty `''`, and an unknown escape. Adjacent string literals are joined, exactly as in
Python: `"ab" "cd"` is `"abcd"`.

### The two roles of a string literal
1. **It initialises a character array.** `char s[4] = "abc";` copies the bytes into `s`. The array may be larger
   (padded with zeros), or *exactly* the length without the NUL (`char s[3] = "abc";` is legal and stores no terminator).
   Longer is an error. The element type may be any of the three character types.
2. **Anywhere else, it is an array, so it decays** (12.6) to a pointer to its first byte. The bytes live in a static,
   read-only, uniquely labelled constant. Writing through that pointer is undefined behaviour.

### Worked example

```c
int puts(char *s);
int main(void) {
    puts("hi");
    return 0;
}
```

```
tmp.0 = GetAddress(string.0)
tmp.1 = puts(tmp.0)
Return(0)
```

```asm
# Linux                               # macOS
    .section .rodata                      .cstring
.Lstring.0:                           Lstring.0:
    .asciz "hi"                           .asciz "hi"
    .text                                 .text
    ...                                   ...
    leaq  .Lstring.0(%rip), %r11          leaq  Lstring.0(%rip), %r11
    movq  %r11, -8(%rbp)                  movq  %r11, -8(%rbp)
    movq  -8(%rbp), %rdi                  movq  -8(%rbp), %rdi
    call  puts@PLT                        call  _puts
```

`.asciz` appends a NUL byte; `.ascii` does not (use it for `char s[3] = "abc"` in static storage). In the emitted text,
escape `"` and `\`, and write every non-printable byte as a three-digit octal escape such as `\012` (newline). On macOS,
`.cstring` is only for NUL-terminated strings.

### Initialising a local array from a string
For `char s[4] = "abc";` the bytes `61 62 63 00` must be written into the stack. One `movb` per byte works, but you can
write them in chunks. x86-64 is little-endian, so those four bytes read as one `int` are `0x00636261`:

```asm
    movl    $6513249, -4(%rbp)      # 0x00636261: "abc\0" in one 4-byte store
```

Use 8-byte chunks while at least 8 bytes remain, then 4, then single bytes. An 8-byte chunk may need a 64-bit immediate,
which your fix-up pass from 12.2 already handles.

### Byte-sized code
Add a `Byte` assembly type: suffix `b` (`movb`), and the 8-bit register names `%al`, `%dl`, `%cl`, `%dil`, `%sil`,
`%r8b`, `%r9b`, `%r10b`, `%r11b`. Widening uses `movsbl`/`movsbq` (sign-extend a byte to 32/64 bits) or `movzbl`/`movzbq`
(zero-extend), all with a register destination. Narrowing to a byte is a `movb` of the low byte. Conversions between
`double` and character types go through `int`: `cvttsd2sil` then truncate; or `movsbl`/`movzbl` then `cvtsi2sdl`.

### Rust notes
C strings are bytes, so store literal contents as `Vec<u8>`, not `String`. A Rust `char` is a 4-byte Unicode scalar,
not a C `char`; byte literals give you a `u8` directly:

```rust
let newline: u8 = b'\n';
```

`i64::from_le_bytes` turns 8 bytes into the immediate for a chunked store. Never emit a Rust `{:?}`-escaped string into
assembly: `\u{…}` escapes are not valid assembler syntax.

## Build
1. **Lexer.** The `char` keyword; character constants; string literals; all escapes above; reject the malformed cases.
2. **Parser.** `char`, `signed char`, `unsigned char` specifiers (reject `signed unsigned char`, `long char`); string
   literal expressions, joining adjacent ones.
3. **Types.** `Char`, `SChar`, `UChar`.
4. **Type checker.** Promotions for character operands; string literals have type `char[n+1]`; array initialisation from a
   string (character element types only; check the length); compile-time conversion of static initialisers to and from
   character types.
5. **Symbol table.** Static string constants with a unique name, the bytes, and a "NUL-terminated" flag.
6. **TACKY.** String initialisers lowered to `CopyToOffset` chunks; other string literals become `GetAddress` of a constant.
7. **Assembly and emitter.** The `Byte` type and register names; `Movsx`/`MovZeroExtend` now record source and
   destination types; `.byte`, `.ascii`, `.asciz`; the Linux and macOS section directives.
8. **Fix-ups.** Byte immediates must fit in 8 bits (truncate `movb $256` to `movb $0`); `movsb*`/`movzb*` need a register
   destination and a non-immediate source.
9. **Test these yourself:** escapes passed to `puts`; `char *names[2] = {"a", "b"};`; `char` parameters past the sixth;
   `unsigned char` arithmetic above 255; a program that prints a line. Arrays without a size (`char s[] = "…"`) are out of
   scope. Then run `--chapter 16`.

   a program wrote through one of them?

## Common pitfalls
- Treating plain `char` as unsigned (that is the ARM convention, not x86-64 System V).
- Forgetting promotions, so `c1 + c2` is computed in one byte and overflows.
- Putting string constants in writable `.data` instead of read-only data.
- Using `.cstring` on macOS for an array that has no NUL terminator.
- Emitting non-printable bytes raw in `.ascii`, or using Rust escape syntax.
