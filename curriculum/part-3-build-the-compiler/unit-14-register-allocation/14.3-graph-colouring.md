# Lesson 14.3 — Graph Colouring
**Part:** 3 — Build the Compiler · **Unit:** 14 — Register Allocation · **Type:** Builds register allocator · **Est. time:** 12–18 h · **Tests:** ch. 20
**Prerequisites:** lessons 14.1, 14.2

## Overview
You turn the interference graph into a register assignment by **colouring** it: give every node one of *k* colours so
that neighbours differ, where each colour stands for a hardware register. You then rewrite the assembly to use those
registers, leave the values that didn't fit to the existing stack-slot pass, and save and restore any callee-saved
registers you used. After this lesson your compiler genuinely allocates registers.

## The lesson

### Colouring is allocation
Take the graph from 14.2 and *k* = 12 colours (14 for `xmm`). If every node gets a colour different from all its
neighbours, then no two interfering values share a register: that is a valid allocation. Finding the *minimum* number
of colours a graph needs is NP-hard (no known efficient algorithm), so compilers use a heuristic that is fast and very
good in practice: **Chaitin–Briggs** colouring, named after the researchers who developed it.

### The key fact
**A node with fewer than *k* neighbours can always be coloured**, whatever colours its neighbours end up with: even if
every neighbour takes a different colour, at most *k* − 1 colours are used up, so one is free. So you can set such a
node aside, colour the rest of the graph, and colour it last. Setting it aside also lowers its neighbours' degrees,
which may let *them* be set aside too. (The **degree** of a node is its number of neighbours.)

### Phase 1: simplify
Build a stack of nodes:
1. While nodes remain in the graph: if some node has degree < *k*, counting only neighbours *still in the graph*,
   remove it and push it on the stack.
2. If every remaining node has degree ≥ *k*, you're stuck. Pick a **spill candidate**: the node with the lowest
   `spill cost / degree`. Remove it and push it anyway. This is the *optimistic* step: it might still get a colour.

### Phase 2: select
Pop nodes off the stack one at a time and put each back into the graph. Look at the colours of its neighbours that
are already coloured, and give it any colour none of them uses. If no colour is free (only possible for a spill
candidate), it becomes an **actual spill**: it stays a pseudo and goes to a stack slot as before.

Nodes come off the stack in the reverse order they went on. Every non-candidate node had fewer than *k* neighbours
in the graph at the moment it was removed, and exactly those neighbours are back when it is popped, so it always finds a colour.

### Spill cost
The **spill cost** estimates how much slower the code gets if this value lives in memory. A simple measure: the number
of times the pseudo appears in the function's instructions. Optionally weight appearances inside loops more (say, ×10
per loop level). Dividing by degree favours spilling high-degree nodes, because removing one relieves many neighbours
at once. **Hard registers get infinite cost**: they are already registers and can never be spilled.

### Hard registers in the graph
Hard-register nodes are coloured like any other. Because all 12 interfere with each other, they receive 12 distinct
colours. Afterwards, each colour *means* the register whose node received it. A pseudo with an edge to `%rdi` therefore
can't get `%rdi`'s colour, which is precisely the constraint 14.2 encoded. (An equivalent, simpler variant: give each
hard register its own colour up front, and run simplify/select over the pseudos only, treating hard-register
neighbours as already coloured.)

### Worked example 1: k = 3, a real spill
```
a: b, c, d      b: a, c, d      c: a, b, d      d: a, b, c, e      e: d
spill costs: a=6, b=5, c=4, d=2, e=3
```
Simplify. `e` has degree 1 < 3: push `e`. Now `a`, `b`, `c`, `d` each have degree 3, so no node is below *k*. Ratios:
`a` 6/3, `b` 5/3, `c` 4/3, `d` 2/3. The lowest is `d`: push `d` as a spill candidate. Now `a`, `b`, `c` have degree 2:
push `a`, `b`, `c`. Stack, top first: `c, b, a, d, e`.

Select. `c` gets colour 0; `b` (neighbour `c`=0) gets 1; `a` (neighbours 0, 1) gets 2. `d`: neighbours `a`, `b`, `c` use
0, 1, 2, so no colour is free: **`d` spills**. `e`: its only neighbour `d` has no colour, so `e` gets 0.

### Worked example 2: k = 2, optimism pays
A 4-cycle `a — b — c — d — a`, all costs 1. Every node has degree 2 = *k*, so push `a` as a spill candidate. Now
`b`, `c`, `d` form a path with degrees 1, 2, 1: push `b`, then `c` and `d` (degrees drop as you go). Select: `d` → 0,
`c` → 1, `b` → 0, `a`: neighbours `b` and `d` are both 0, so `a` gets 1. **No spill.** A pessimistic allocator, one
that spills a candidate immediately, would have needlessly spilled `a`. This is Briggs's improvement to Chaitin.

### Choosing among free colours
When a pseudo has several free colours, it matters which you pick. A **caller-saved** register costs nothing extra:
if the value were live across a call, the call's edges would already have ruled those registers out. A
**callee-saved** register costs a push and a pop in the function. So prefer colours that map to caller-saved registers.

### Rewriting the function
1. Replace every coloured pseudo with its register, printed at the operand's size: `%eax` for a 4-byte value, `%rax`
   for 8 bytes, `%al` for the byte written by `setCC` (`%r8d`, `%r8`, `%r8b` for the numbered registers).
2. Delete any `mov` whose source and destination are now the same register.
3. Leave uncoloured pseudos alone. Your existing pseudo-replacement and fix-up passes give them stack slots and patch
   memory operands, using `%r10`/`%r11`, which is why those stay reserved. (Textbook Chaitin rebuilds the graph after
   inserting spill code; your fix-up pass makes that unnecessary.)

### Saving callee-saved registers
Record which of `bx, r12, r13, r14, r15` were assigned to any pseudo. In the prologue, push them **after**
`subq $N, %rsp`, so the stack slots at negative offsets from `%rbp` stay where pseudo replacement put them. Before
**every** `ret`, pop them in reverse order, then `movq %rbp, %rsp; popq %rbp; ret`.
```
    pushq %rbp
    movq  %rsp, %rbp
    subq  $N, %rsp          # stack slots for spilled pseudos
    pushq %rbx              # callee-saved registers this function uses
    pushq %r12
    ...
    popq  %r12              # before each ret, in reverse order
    popq  %rbx
    movq  %rbp, %rsp
    popq  %rbp
    ret
```
Alignment (recall 11.3): `%rsp` must be 16-aligned at every `call`. After the prologue's `pushq %rbp` it is aligned, so
choose `N` such that `N + 8 × (number of registers pushed)` is a multiple of 16. With 3 registers pushed and 20 bytes
of slots: 20 + 24 = 44, so round 20 up to `N` = 40 (40 + 24 = 64).

### The pipeline per function
```
assembly with pseudos
  -> liveness -> interference graph -> spill costs -> colour -> rewrite
  -> pseudo replacement (for spilled/static/aggregate pseudos) -> fix-up -> emit
```
Run the integer and `xmm` classes separately if you have `double`.

## Build

**Practice first (paper).** Run simplify and select on: `a: b, c`, `b: a, c, d`, `c: a, b, d`, `d: b, c, e`,
`e: d`, with *k* = 2 and costs a=1, b=4, c=3, d=2, e=5. Which node spills? Then repeat with *k* = 3.

**Spec.** Input: one function's assembly and its interference graph. Output: assembly where allocated pseudos are hard
registers, plus the set of callee-saved registers the function uses.
- **Spill costs** for every node; hard registers infinite.
- **Colouring:** simplify with optimistic spill selection, then select. Result: a map from pseudo to hard register for
  coloured pseudos only.
- **Colour-to-register mapping** via the hard-register nodes' colours, preferring caller-saved colours for pseudos.
- **Rewrite:** replace allocated pseudos at the right size; remove self-moves; leave the rest for pseudo replacement.
- **Prologue/epilogue:** the used callee-saved set travels with each function (a field on the assembly function or a
  backend symbol-table entry); the emitter pushes and pops them; frame-size rounding accounts for them.
- **Edge cases:** a function with no pseudos; more than 12 simultaneously live values (forces real spills); values live
  across calls (callee-saved or spill); a function using no callee-saved registers (prologue unchanged); several `ret`s.

**Suggested order.**
1. Spill costs, then simplify/select as a pure function on a graph. Unit-test both worked examples.
2. Colour-to-register mapping and rewrite; at first, temporarily allow only caller-saved colours so no save/restore is needed.
3. Add callee-saved registers with save/restore and alignment.
4. Run chapter 20 without coalescing, then all earlier chapters with optimisations on.

## Check your understanding
1. Why can a node of degree < *k* always be coloured, whatever happens to the others?
2. Why is it safe to push a spill candidate instead of spilling it at once?
3. Why divide spill cost by degree?
4. In worked example 2, what would a pessimistic allocator have done, and what did optimism save?
5. Why do callee-saved pushes go after `subq $N, %rsp` and not before it?

## Common pitfalls
- Counting degree against the original graph instead of only the neighbours still present during simplify.
- Letting a hard register become a spill candidate.
- Forgetting operand-size register names when rewriting (`%eax` vs. `%rax`), or byte names for `setCC`.
- Popping callee-saved registers in the wrong order, or only before one of several `ret`s.
- Breaking 16-byte alignment at calls once registers are pushed.
