# Lesson 3.5 — Loops
**Unit:** 3 — Variables, Scope and Control Flow · **Type:** Builds loops + loop-labelling pass · **Est. time:** 5–7 h · **Tests:** ch. 8
**Prerequisites:** lesson 3.4

## Learning goals
- Lower `while`, `do … while` and `for` into labels and conditional jumps.
- Understand how `break` and `continue` find their target loop, and why that is a separate semantic pass.
- Handle the `for` header's own scope (`for (int i = 0; …)`).
- Annotate AST nodes with information computed after parsing (a label field filled in by a pass).
- Use `Option` fields and a stack-like "current loop" parameter in a recursive Rust walk.

## Key ideas
**Grammar additions.**
```
<statement> ::= ... | "break" ";" | "continue" ";"
              | "while" "(" <exp> ")" <statement>
              | "do" <statement> "while" "(" <exp> ")" ";"
              | "for" "(" <for-init> [ <exp> ] ";" [ <exp> ] ")" <statement>
<for-init>  ::= <declaration> | [ <exp> ] ";"
```
All three `for` header parts are optional; a missing condition means "true", so `for (;;)` loops forever.

**Loop labelling.** `break` exits the innermost enclosing loop; `continue` jumps to its "next iteration" point.
After parsing, a `break` doesn't know which loop it belongs to. A small pass walks the tree carrying the
*current loop label* (none at the top): each loop gets a fresh label (e.g. `loop.7`) and passes it down to its
body; each `break`/`continue` records the label it sees; a `break`/`continue` with no current label is an error.
Run it after variable resolution.

**Lowering** (`L` is the loop's label; derive `continue_L`, `break_L`, `start_L` from it):

`while (c) body`:
```
Label(continue_L)
<c → v>; JumpIfZero(v, break_L)
<body>
Jump(continue_L)
Label(break_L)
```
`do body while (c);`:
```
Label(start_L)
<body>
Label(continue_L)
<c → v>; JumpIfNotZero(v, start_L)
Label(break_L)
```
`for (init; c; post) body`:
```
<init>
Label(start_L)
<c → v>; JumpIfZero(v, break_L)     (omitted if no condition)
<body>
Label(continue_L)
<post>                              (result discarded)
Jump(start_L)
Label(break_L)
```
`break` → `Jump(break_L)`; `continue` → `Jump(continue_L)`. Note that `continue` in a `for` still runs `post`,
and in a `do` loop it still evaluates the condition.

**Worked example.**
```c
int main(void) { int s = 0; for (int i = 0; i < 3; i = i + 1) s = s + i; return s; }
```
TACKY:
```
Copy(0, s.0)
Copy(0, i.1)
Label(start_loop.2)
Binary(LessThan, i.1, 3, tmp.3); JumpIfZero(tmp.3, break_loop.2)
Binary(Add, s.0, i.1, tmp.4); Copy(tmp.4, s.0)
Label(continue_loop.2)
Binary(Add, i.1, 1, tmp.5); Copy(tmp.5, i.1)
Jump(start_loop.2)
Label(break_loop.2)
Return(s.0)
```

**Scope of the `for` header.** `for (int i = 0; …) body` opens a new scope for `i`; the body (if it is a block)
opens another one inside it, so `for (int i = 0; i < 3; i = i + 1) { int i = 9; }` is legal shadowing.

## Questions the tutor should ask you
1. Why can't `break` be resolved during parsing as easily as during a separate walk? (Hint: what would the parser have to carry?)
2. Where does `continue` jump in a `for` loop, and why not straight to the condition?
3. In `while (a) { while (b) break; x = 1; }`, which loop does the `break` exit? Trace your pass.
4. What new scope does a `for` loop create, and when does `i` stop being visible?
5. Why does `do … while` use `JumpIfNotZero` at the bottom, while `while` uses `JumpIfZero` at the top?
6. Could you reuse the loop's unique label as the stem for all three of its jump targets? Why is that safe?

## What you build
- **Lexer:** `while`, `do`, `for`, `break`, `continue`.
- **AST:** the five new statements; `For` holds an init (declaration *or* optional expression), optional condition,
  optional post and a body. Loops, `break` and `continue` carry a label field that the labelling pass fills in.
- **Parser:** the grammar above. Watch the `;` handling: a `for` init declaration already consumes its `;`.
- **Resolution:** a `for` header gets its own scope; recurse into all loop parts.
- **Loop-labelling pass:** annotate as above; error on `break`/`continue` outside a loop.
- **TACKY:** the lowerings above.
- **Must reject:** `break;` or `continue;` outside any loop, `do x = 1 while (y);` (missing `;` before `while`),
  `while () …`, `for (int i = 0, j = 0; …)` (no comma operator), a declaration as a loop body (`while (1) int a;`),
  using a `for`-header variable after the loop, redeclaring a header variable in the header's own scope.
- **Must accept:** `for (;;) { … break; }`, empty bodies (`while (x) ;`), nested loops with `break`/`continue` at each level,
  `continue` inside an `if` inside a loop.

## Rust focus
- `Option<String>` (or a newtype) for labels filled in by a later pass; decide whether passes return new nodes or annotate in place.
- An enum for the `for` init: `InitDecl(Declaration) | InitExp(Option<Exp>)`; nested `Option` matching ([Book ch. 6.2](https://doc.rust-lang.org/book/ch06-02-match.html)).
- Passing `Option<&str>` down a recursive walk as the "current loop" ([std::option::Option::as_deref](https://doc.rust-lang.org/std/option/enum.Option.html#method.as_deref)).
- Newtype wrappers to keep label strings from being confused with variable names ([Book: newtype pattern](https://doc.rust-lang.org/book/ch20-02-advanced-traits.html)).

## Common pitfalls
- `continue` in a `for` loop jumping to the condition and skipping `post`, causing an infinite loop.
- Forgetting that a missing `for` condition means true (emitting a jump on an undefined value).
- Not giving the `for` header its own scope, so `for (int i …) …; int i;` is wrongly rejected or a header `i` leaks out.
- Labelling `break` with the *outermost* loop by not replacing the current label when entering a nested loop.
- Discarding `post`'s side effects (its value is unused, but the assignment must happen).
