# Lesson 4.5 — Storage & Linkage
**Unit:** 4 — Functions and Whole Programs · **Type:** Builds global/static variables · **Est. time:** 8–12 h · **Tests:** ch. 10
**Prerequisites:** lesson 4.4

## Learning goals
- Separate three independent properties of an identifier: **scope**, **linkage** (none/internal/external) and **storage duration** (automatic/static).
- Apply the rules for `static` and `extern` at file scope and block scope, including tentative definitions.
- Emit static data in `.data` and `.bss`, control visibility with `.globl`, and address it RIP-relatively.
- Grow the symbol table to record linkage and initial values, and drive TACKY/codegen decisions from it.
- Model "one of several states with a precedence order" (initializer kinds) cleanly with Rust enums.

## Key ideas
**Specifiers.** A declaration now starts with a list of specifiers in any order: exactly one `int`, and at most one of
`static`/`extern`. `static int x;` and `int static x;` are the same. Parameters and `for` headers can't have a storage class.

**The three properties.**
| Declaration | Linkage | Storage |
|---|---|---|
| file scope, no specifier | external | static |
| file scope, `static` | internal | static |
| file scope or block, `extern` | that of a prior visible declaration, else external | static |
| block scope, no specifier | none | automatic |
| block scope, `static` | none | static |
Functions always have static storage; `static` gives internal linkage, nothing/`extern` behaves like `extern`.
Block-scope `static` *function* declarations are illegal.

**File-scope variable rules** (type checker):
- Initializer must be a **constant** (no expressions, no other variables).
- Initial value kinds: *initial(n)* if initialized; *tentative* if no initializer and no `extern`; *no initializer*
  if `extern` without initializer. Merging declarations: two *initial*s → **conflicting definitions** error; otherwise
  initial beats tentative beats no-initializer.
- Linkage must agree across declarations: `static int x; int x;` is an error; `static int x; extern int x;` is fine
  (`extern` adopts internal linkage).
- A tentative definition with no real definition becomes a definition initialized to 0, so `int x; int x;` is legal.

**Block-scope rules:** `extern int x;` refers to the file-scope entity and must not have an initializer; the resolver
does not rename it (it has linkage), and it conflicts with a no-linkage `x` in the same block. `static int n = 3;`
inside a function is renamed like any local, but lives in static storage, is initialized *once* (at load time,
not each call) and requires a constant initializer (default 0).

**Code generation.** TACKY gains a top-level `StaticVariable(name, global, init)` alongside functions (which gain a
`global` flag). Generate them from the symbol table: *initial(n)* → emit with n; *tentative* → emit with 0; *no
initializer* → emit nothing (defined elsewhere). In the back end, a pseudo whose symbol has static storage is
replaced with a `Data(name)` operand instead of a stack slot. `Data` is memory: the fix-up rules for `Stack`
(no mem→mem `mov`, no memory `idiv` operand, etc.) apply to it too. Every `Data` operand is reached with RIP-relative
addressing, which is position-independent and required by macOS.

**Worked example.**
```c
static int counter = 5;
int total;
int bump(void) { static int calls; calls = calls + 1; counter = counter + 1; return calls; }
```
Symbols: `counter` (internal, initial 5), `total` (external, tentative), `calls.0` (no linkage, static, tentative → 0), `bump` (external, defined).
macOS emission (Linux: drop the `_`):
```
    .globl _total
    .bss
    .balign 4
_total:
    .zero 4
    .data
    .balign 4
_counter:                       # no .globl: internal linkage
    .long 5
    .bss
    .balign 4
_calls.0:
    .zero 4
    .globl _bump
    .text
_bump:
    pushq %rbp
    movq  %rsp, %rbp
    subq  $16, %rsp
    movl  _calls.0(%rip), %r10d   # mem->mem fix-up
    movl  %r10d, -4(%rbp)         # tmp.1 = calls.0
    addl  $1, -4(%rbp)
    movl  -4(%rbp), %r10d
    movl  %r10d, _calls.0(%rip)   # calls.0 = tmp.1
    ...
```
Zero-initialized objects go in `.bss` (no bytes in the file); non-zero ones in `.data`. Compare with `clang -S` / `gcc -S`
output on Godbolt: real compilers may use `.comm` or `.zerofill` forms, but the simple directives above assemble on both platforms.

## Questions the tutor should ask you
1. What is the scope, linkage and storage duration of: a file-scope `static int a;`, a block-scope `static int b;`, a block-scope `extern int c;`?
2. Why is `int x; int x = 3;` legal at file scope but `int x = 1; int x = 3;` an error?
3. A block-scope `static int n = 0;` in a function called three times: how many times is `n` initialized, and where does that happen in the generated code?
4. Why must the resolver *not* rename a block-scope `extern int x;`, but must rename a block-scope `static int x;`?
5. Why can't you emit `movl _a(%rip), _b(%rip)`? Which existing pass fixes it?
6. What would happen at link time if two files both had `static int helper(void) { … }`? If both had `int g = 1;`?

## What you build
- **Parser:** specifier lists (validated: one type, ≤ 1 storage class); top-level variable declarations; reject storage classes on params and in `for` init.
- **Resolver:** file-scope identifiers keep their names; block-scope `extern` keeps its name and has linkage; same-block conflicts with a no-linkage name are errors.
- **Type checker / symbol table:** attributes per entry: function (defined, global), static (initial value kind, global), local. Apply all rules above.
- **TACKY:** `global` on functions; `StaticVariable` top-level items generated from the table; skip TACKY code for `static`/`extern` local declarations
  (their initialization is static, not an instruction).
- **Assembly:** `Data(name)` operand; pseudo replacement consults the table; fix-up treats `Data` as memory; emitter prints `.globl` only for global symbols,
  `.data`/`.bss`/`.text` section switches, `.balign 4`, `.long n` / `.zero 4`, and `_name(%rip)`.
- **Must reject:** `static extern int x;`, `int int x;`, `static` without a type, `int f(static int a)`, `for (static int i = 0; …)`, non-constant file-scope or
  static-local initializers, `extern int x = 1;` in a block, a block-scope `static int f(void);`, conflicting linkage (`int x; static int x;`), two initialized
  definitions of one variable, a variable and a function with the same file-scope name, an `extern` in a block conflicting with a same-block local, a local
  `extern int f;` where `f` is a function.
- **Edge cases:** `extern int x = 3;` at file scope (legal definition), a tentative definition followed by a real one, static locals with the same source name in
  two functions, using a global defined in another file (compiled with `-c`), recursion that relies on a static counter.

## Rust focus
- Enums for initializer state (`Tentative | Initial(i64) | NoInitializer`) and attributes; a small method that merges two states and returns `Result`
  ([Book ch. 6.1](https://doc.rust-lang.org/book/ch06-01-defining-an-enum.html)).
- Iterating a `HashMap` to emit statics; sorting keys for deterministic output (`HashMap` order is unspecified)
  ([HashMap iteration order](https://doc.rust-lang.org/std/collections/struct.HashMap.html), [BTreeMap](https://doc.rust-lang.org/std/collections/struct.BTreeMap.html)).
- `matches!` for compact attribute checks, e.g. `matches!(entry.attrs, Attrs::Static { .. })` ([matches!](https://doc.rust-lang.org/std/macro.matches.html)).
- Parsing an unordered specifier list into counted flags; reporting precise errors with your error enum.
- Passing the symbol table by shared reference to codegen passes (`&SymbolTable`) while each pass owns the IR it rewrites.

## Common pitfalls
- Emitting a `Copy` instruction for a static local's initializer, so it is reset on every call.
- Forgetting `.text` before functions after emitting data sections (code ends up in `.data` or `.bss`).
- Marking `static` variables `.globl`, which breaks internal linkage (duplicate-symbol link errors across files).
- Emitting storage for `extern` declarations with no initializer (multiple-definition link errors).
- Not treating `Data` operands as memory in the fix-up pass (`idiv`, `cmp`, mem→mem `mov`).
- Non-deterministic output order from `HashMap`, making diffs and debugging painful.
