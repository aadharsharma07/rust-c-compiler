# Lesson 4.4 — Calls in Assembly
**Unit:** 4 — Functions and Whole Programs · **Type:** Builds function codegen → printing programs · **Est. time:** 6–10 h · **Tests:** ch. 9
**Prerequisites:** lessons 4.2, 4.3

## Learning goals
- Lower TACKY `FunCall` to System V-compliant assembly: register args, stack args, padding, clean-up, result copy.
- Copy incoming parameters from registers and caller stack slots into the callee's own pseudoregisters.
- Emit several functions per file, with `.globl`, correct symbol names per platform, and per-function stack sizes.
- Link with libc and with object files built by another compiler; add `-c` to the driver.
- Extend register and instruction enums and make the emitter size-aware (`%edi` vs. `%rdi`).

## Key ideas
**New assembly constructs.** Registers `DI SI DX CX R8 R9` (alongside `AX`, `R10`, …); instructions
`Push(operand)`, `Call(name)`, and a stack de-allocation (`addq $n, %rsp`) to match your stack allocation
(`subq $n, %rsp`). Operands may now be `Stack(+16)` etc. (positive offsets = caller's stack args).

**Function prologue: copy parameters in.** For parameter *i* (0-based): if *i* < 6, `Mov(Reg(argreg[i]), Pseudo(p))`;
otherwise `Mov(Stack(16 + 8·(i−6)), Pseudo(p))`. After this, parameters are ordinary pseudoregisters and the rest of
your back end doesn't care that they're parameters.

**Lowering `FunCall(f, args, dst)`.**
1. Let *k* = number of stack args (`max(0, n − 6)`). If *k* is odd, allocate 8 bytes of padding.
2. Move the first six arguments into `DI, SI, DX, CX, R8, R9`.
3. For the remaining arguments **in reverse order**: if the operand is an immediate or register, `Push` it; otherwise
   `Mov` it into `AX` and `Push(Reg(AX))`. (Pushing a 4-byte stack slot directly would read 8 bytes, 4 of which aren't yours.)
4. `Call(f)`, then deallocate `8·k + padding` bytes if non-zero.
5. `Mov(Reg(AX), dst)`.
Because TACKY already evaluated every argument into a value *before* the `FunCall`, nested calls like `f(g(1), 2)`
can't clobber argument registers half-way through.

**Stack frame size.** Pseudo-replacement is now per function. Round each function's total to a multiple of 16 so the
alignment reasoning from 4.3 holds.

**Emission and symbols.** Every function gets `.globl`. On macOS, prefix all symbols with `_` and call as
`call _f`. On Linux, a call to a function *not defined in this translation unit* is written `call f@PLT` (the symbol
table from 4.2 tells you which); calls to local definitions are just `call f`. macOS has no `@PLT` syntax.
Size-aware register printing: `movl %edi, -4(%rbp)` but `pushq %rax`.

**Worked example.**
```c
int putchar(int c);
int twice(int x) { return x + x; }
int main(void) { putchar(twice(33)); return 0; }   /* prints "B" (ASCII 66) */
```
macOS assembly (trailing `Return(0)` code omitted):
```
    .globl _twice
_twice:
    pushq %rbp
    movq  %rsp, %rbp
    subq  $16, %rsp
    movl  %edi, -4(%rbp)        # x.0 <- param 1
    movl  -4(%rbp), %r10d
    movl  %r10d, -8(%rbp)       # tmp.1 = x.0
    movl  -4(%rbp), %r10d
    addl  %r10d, -8(%rbp)       # tmp.1 += x.0
    movl  -8(%rbp), %eax
    movq  %rbp, %rsp
    popq  %rbp
    ret

    .globl _main
_main:
    pushq %rbp
    movq  %rsp, %rbp
    subq  $16, %rsp
    movl  $33, %edi
    call  _twice
    movl  %eax, -4(%rbp)        # tmp.2
    movl  -4(%rbp), %edi
    call  _putchar              # Linux: call putchar@PLT
    movl  %eax, -8(%rbp)        # tmp.3 (unused)
    ...
```

**Driver `-c`.** From chapter 9 on, the test suite compiles some files with your compiler and others with the system
compiler, then links them. `rcc -c foo.c` must assemble to `foo.o` and stop (no linking). Without `-c`, link as before;
the system `gcc`/`clang` links libc automatically, which is how `putchar` resolves.

## Questions the tutor should ask you
1. Why does a parameter get copied out of `%edi` into a stack slot right at the start of the function?
2. Why push stack arguments in reverse order, and why pad *before* pushing rather than after?
3. Why is it safe to use `%rax` as a scratch register when pushing an argument from memory?
4. What does `f(g(1), h(2))` look like in TACKY, and why does that ordering protect `%edi`?
5. How does the emitter decide between `call f` and `call f@PLT` on Linux? What changes on macOS?
6. What goes wrong if two functions share one pseudo → stack-offset map?

## What you build
- **TACKY → assembly:** parameter copy-in; `FunCall` lowering as specified; per-function pseudo replacement and 16-byte rounding.
- **Assembly AST:** new registers, `Push`, `Call`, stack deallocation; a program becomes a list of functions.
- **Fix-up:** confirm memory-to-memory moves from `Stack(16)` into locals are fixed; immediates/registers in `Push` need no fix-up.
- **Emitter:** `.globl` per function; register names in 1-, 4- and 8-byte forms as needed; platform-specific call syntax.
- **Driver:** `-c` produces an object file; preserve all existing stage flags.
- **Must handle:** 0–6 register args, >6 args with odd and even counts, recursion (`fib`), mutual recursion via prototypes,
  calls as arguments, calling `putchar` from libc, functions defined in one file and called from another (`-c` + link).
- **Errors:** none new (type errors are caught in 4.2), but an assembler or linker failure must surface as a non-zero exit.

## Rust focus
- Splitting a slice: `let (reg_args, stack_args) = args.split_at(args.len().min(6));` shows `split_at` in isolation
  ([slice::split_at](https://doc.rust-lang.org/std/primitive.slice.html#method.split_at)); `.iter().rev()` for pushing.
- `zip` arguments with a `const` array of registers ([Iterator::zip](https://doc.rust-lang.org/std/iter/trait.Iterator.html#method.zip)).
- A `HashMap` created fresh per function for pseudo offsets; returning the frame size alongside the rewritten instructions.
- Matching on `(register, size)` tuples in the emitter; `cfg!(target_os = "macos")` or a runtime flag for platform differences
  ([cfg! macro](https://doc.rust-lang.org/std/macro.cfg.html)).
- `std::process::Command` for the `-c` path and checking `status.success()` ([Command](https://doc.rust-lang.org/std/process/struct.Command.html)).

## Common pitfalls
- Forgetting to deallocate after the call, or deallocating only the pushed bytes and not the padding.
- Pushing with a 4-byte register name (`pushl` doesn't exist in 64-bit mode; it must be `pushq %rax`).
- Off-by-8 errors reading stack parameters (`8(%rbp)` is the return address; the first stack param is at `16(%rbp)`).
- Not rounding the frame to 16, so calls into libc crash intermittently.
- Missing `_` prefix on macOS for callee names, or emitting `@PLT` on macOS.
- Resetting the label/temporary counter per function, so two functions emit the same label ("symbol already defined").
