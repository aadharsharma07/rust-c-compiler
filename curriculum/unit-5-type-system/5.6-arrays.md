# Lesson 5.6 — Arrays
**Unit:** 5 — A Real Type System · **Type:** Builds Arrays, subscripts, initialisers · **Est. time:** 10–14 h · **Tests:** ch. 15
**Prerequisites:** lessons 5.1–5.5

## Learning goals
- Parse array declarators, including multi-dimensional arrays and mixtures with pointers (`int *a[3]` vs. `int (*a)[3]`).
- Explain *array-to-pointer decay* and the few places where it does not happen.
- Lower subscripting and pointer arithmetic, scaling integers by the size of the element type.
- Type-check and lower compound initialisers (`{1, 2, 3}`, nested, partial), for both automatic and static arrays.
- Use `lea` with indexed addressing (`(%rax,%rdx,4)`), and align arrays per System V.

## Key ideas
**Array types.** `Array(element type, n)` has size `n × size(element)`. `int a[2][3]` is an array of 2 arrays of 3
`int`s: 24 bytes. A declarator suffix `[n]` binds tighter than a prefix `*`, so `int *a[3]` is an array of 3 pointers,
while `int (*a)[3]` is a pointer to an array of 3 ints. The size must be a positive integer constant.

**Decay.** An expression of array type is almost never used as an array: it is converted to a pointer to its first
element. Do this in the type checker by wrapping every array-typed expression in an implicit address-of node, *except*
when it is the operand of `&` (and later `sizeof`) or a string literal initialising a `char` array (lesson 5.7). Arrays
are therefore not lvalues you can assign to: `a = b` is an error, but `a[0] = 1` is fine.

**Subscripts are pointer arithmetic.** `a[i]` means `*(a + i)`; one operand must be a pointer (after decay) and the
other an integer, so `2[a]` is legal C. Pointer arithmetic is scaled: `p + i` advances by `i × sizeof(*p)` bytes.
Rules:
- `ptr + int`, `int + ptr`, `ptr - int` → pointer type. Convert the integer to `long` first.
- `ptr - ptr` (same type) → `long`, the byte difference divided by the element size.
- `<`, `<=`, `>`, `>=` on two pointers of the same type (unsigned compare).

**Worked example.**

```c
int main(void) {
    int a[3] = {1, 2, 3};
    long i = 2;
    return a[i];
}
```

```
CopyToOffset(1, a, 0)
CopyToOffset(2, a, 4)
CopyToOffset(3, a, 8)
i = 2L
tmp.0 = GetAddress(a)
tmp.1 = AddPtr(tmp.0, i, 4)     # ptr, index, scale
tmp.2 = Load(tmp.1)
Return(tmp.2)
```

```asm
    movl    $1, -12(%rbp)
    movl    $2, -8(%rbp)
    movl    $3, -4(%rbp)
    movq    $2, -24(%rbp)           # i
    leaq    -12(%rbp), %r11
    movq    %r11, -32(%rbp)         # tmp.0
    movq    -32(%rbp), %rax
    movq    -24(%rbp), %rdx
    leaq    (%rax,%rdx,4), %r11     # base + index*4
    movq    %r11, -40(%rbp)         # tmp.1
```

The `Indexed(base, index, scale)` operand only allows scales 1, 2, 4 and 8. For other element sizes (e.g. an
`int[3]` row of 12 bytes) multiply the index first with `imulq $12, %rdx`. A constant index can fold into a
displacement: `leaq 8(%rax), %r11`.

**Aggregates in the back end.** An array is not a scalar, so it cannot live in a pseudoregister of a fixed width.
Give the assembly AST a byte-array assembly type with a size and alignment, and a `PseudoMem(name, offset)` operand
for "byte `offset` inside aggregate `name`". Pseudoregister replacement turns it into a `Memory(BP, …)` slot.
System V rule: an array of **16 bytes or more** is 16-byte aligned, on the stack and in static storage. Smaller
arrays use their element's alignment.

**Initialisers.** A compound initialiser lists elements in order; nested braces initialise sub-arrays. Missing
trailing elements are zero; extra elements are an error. In a function, lower each scalar to `CopyToOffset`. For
`static int a[4] = {1, 2};` emit `.long 1`, `.long 2`, `.zero 8`; a fully zero static array can go in `.bss`.

## Questions the tutor should ask you
1. What is the type of `a`, `a[1]` and `&a` for `int a[2][3]`? What does each decay to?
2. Why is decay done in the type checker rather than in TACKY generation?
3. For `long *p`, how many bytes does `p + 3` move? What about `p - q`, and what type does it have?
4. Why must the subscript index be converted to `long` before scaling?
5. Why is `int a[3]; a = b;` an error but `int *p; p = b;` fine?
6. Where does a 20-byte local array have to start, and why?

## What you build
- **Parser:** `[constant]` declarator suffixes (also in abstract declarators for casts); postfix `[expr]` subscripts
  at the highest precedence; compound initialisers `{…}` with an optional trailing comma.
- **Types:** `Array(element, size)`. Function parameters declared as arrays are *adjusted* to pointers. A function
  cannot return an array; casting *to* an array type is an error.
- **Type checker:** decay; subscript, pointer `+`/`-` and relational comparison rules; reject a non-constant or zero/negative
  array size, a compound initialiser for a scalar, a scalar initialiser for an array, too many elements, and assigning to an array.
  Static initialisers become a list of values plus zero-fill entries.
- **TACKY:** `AddPtr(ptr, index, scale, dst)` and `CopyToOffset(src, dst, offset)`. `ptr - ptr` becomes a `Subtract`
  then a `Divide` by the element size.
- **Assembly:** `Indexed` operand, `PseudoMem`, byte-array assembly type; `lea` for `AddPtr`; `.zero n` in static data.
  The backend symbol table records size and alignment of aggregates.
- **Edge cases:** multi-dimensional subscripts `a[i][j]`; pointer to a row `int (*row)[3] = a;`; negative indices `p[-1]`;
  arrays as function arguments; static and `extern` arrays; arrays of `double` and of pointers; compound assignment `+=` on pointers if you implemented compound assignment.

## Rust focus
- **Recursive initialisers.** A nested initialiser is a tree of single values and lists; walking it alongside the
  target type is a good exercise in recursion with two matched enums.
- **Iterators.** [`zip`](https://doc.rust-lang.org/std/iter/trait.Iterator.html#method.zip),
  [`enumerate`](https://doc.rust-lang.org/std/iter/trait.Iterator.html#method.enumerate) and
  [`chain`](https://doc.rust-lang.org/std/iter/trait.Iterator.html#method.chain) express "each element with its offset"
  without index arithmetic.
- **Size arithmetic.** Use `usize`/`i64` deliberately and check overflow for huge arrays
  ([`checked_mul`](https://doc.rust-lang.org/std/primitive.usize.html#method.checked_mul)).

## Common pitfalls
- Getting the declarator order wrong, so `int a[2][3]` becomes 3 arrays of 2.
- Decaying the operand of `&`, which makes `&a` a pointer-to-int instead of pointer-to-array.
- Scaling by the size of the *pointer* (8) instead of the size of the *element*.
- Forgetting that `CopyToOffset` offsets are bytes, not element indices.
- Using `%r10`/`%r11` as the base or index of an `Indexed` operand that a fix-up then clobbers.
- Treating the type of `ptr - ptr` as a pointer, or forgetting to divide by the element size.
