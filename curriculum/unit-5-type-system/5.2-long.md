# Lesson 5.2 — long
**Unit:** 5 — A Real Type System · **Type:** Builds `long` · **Est. time:** 10–14 h · **Tests:** ch. 11
**Prerequisites:** lesson 5.1

## Learning goals
- Explain sign extension and truncation in two's complement, and why both are needed between `int` and `long`.
- Emit correctly sized instructions: longword (`l`, 32-bit) vs. quadword (`q`, 64-bit) operands and register names.
- Handle 64-bit immediates and the instructions that cannot encode them.
- Lay out mixed-size values on the stack with correct alignment.
- Build a *backend symbol table* that records the assembly type of every object.

## Key ideas
**Sign extension and truncation.** Widening a signed 32-bit value to 64 bits copies its sign bit into the
upper 32 bits: `-1` (`0xFFFFFFFF`) becomes `0xFFFFFFFFFFFFFFFF`. x86-64 does this with `movslq src, %reg`
(AT&T name for `movsx` from 32 to 64 bits; the destination must be a register). Narrowing a `long` to an
`int` keeps the low 32 bits, so a `movl` of the source's low half is enough. In TACKY these become two new
instructions: `SignExtend(src, dst)` and `Truncate(src, dst)`. A `Cast` between identical types is just a `Copy`.

**Every assembly instruction now has an operand size.** Give `Mov`, `Unary`, `Binary`, `Cmp`, `Idiv` and
`Push` an *assembly type*: `Longword` or `Quadword`. The emitter picks the suffix and register names from it:
`%eax`/`%rax`, `%r10d`/`%r10`, `%edi`/`%rdi`. Division widens differently too: `cdq` sign-extends `%eax` into `%edx`,
while `cqo` sign-extends `%rax` into `%rdx`.

**Worked example.**

```c
long add(int a, long b) { return a + b; }
```

```
add(a, b):
    tmp.0 = SignExtend(a)
    tmp.1 = tmp.0 + b
    Return(tmp.1)
```

```asm
    movl    %edi, -4(%rbp)        # a: 4 bytes
    movq    %rsi, -16(%rbp)       # b: 8 bytes, 8-aligned
    movslq  -4(%rbp), %r11        # fix-up: movslq needs a register destination
    movq    %r11, -24(%rbp)       # tmp.0
    movq    -24(%rbp), %r10
    movq    %r10, -32(%rbp)       # tmp.1 = tmp.0
    movq    -16(%rbp), %r10
    addq    %r10, -32(%rbp)       # tmp.1 += b
    movq    -32(%rbp), %rax
```

Note the 4-byte gap at `-12(%rbp)`: an 8-byte value must sit at an 8-byte-aligned address.

**64-bit immediates.** Almost every x86-64 instruction encodes at most a 32-bit immediate, which the CPU
sign-extends to 64 bits. `addq $4294967296, %rax` cannot be encoded. The one exception is a move of a 64-bit
immediate into a *register*: `movabsq $4294967296, %r10`. (GNU `as` and Apple `as` also accept `movq $big, %r10`
and choose the `movabs` encoding for you.) Your fix-up pass must rewrite every quadword instruction whose
immediate falls outside the `i32` range: load it into `%r10` first, then use the register. This applies to `add`, `sub`, `imul`, `cmp`, `push`,
and `mov` to memory.
For a `movl` whose constant does not fit, emit the truncated low 32 bits so the assembler does not warn.

**The backend symbol table.** Pseudoregister replacement now needs each variable's *size* and *alignment*,
and the emitter still needs to know whether a function is defined in this file. Convert the front-end symbol
table into a backend table that maps each name to either an object entry (assembly type, static or not) or a
function entry (defined or not). Build it once after TACKY generation, and later passes only look things up.

**Static data.** A `static long` goes in `.data` with `.balign 8` and `.quad 5` (or in `.bss` with
`.zero 8` if it is zero). A `static int` keeps `.balign 4` / `.long`. Prefer `.balign`, because on macOS `.align n`
means 2ⁿ bytes.

**The call stack.** `pushq` always pushes 8 bytes. Pushing a longword *memory* argument would read 4 bytes
beyond the variable, so move it into `%eax` first and `pushq %rax`. (The upper half is garbage, which
the callee will ignore.)

## Questions the tutor should ask you
1. What bit pattern does `(long) -5` have, and which instruction produces it from a 32-bit `-5`?
2. Why does `Truncate` need no special instruction?
3. Why must the fix-up pass check immediates for `addq` but not for `addl`?
4. Which passes read the backend symbol table, and what does each need from it?
5. Your stack allocator hands out offsets for `int, long, int`. Draw the frame. How many bytes are wasted?
6. Why does division need `cqo` instead of `cdq` for `long` operands?

## What you build
- **TACKY:** `SignExtend` and `Truncate`. Constants carry int or long values. TACKY static variables carry their
  type and a typed initial value. Temporaries get an entry in the symbol table with their type, because codegen
  must know each temporary's size.
- **Assembly AST:** an assembly type on sized instructions; `Movsx` (emitted `movslq`); `Cdq` and `Cqo`
  (or one instruction with a type); quad-sized registers. Static variables carry an alignment.
- **Backend symbol table** as described above. Pseudoregister replacement uses it for size and alignment,
  rounding the frame size up to a multiple of 16.
- **Fix-ups:** `movslq` with a memory destination or immediate source; out-of-range quadword immediates
  (via `%r10`); `imulq` with a memory destination; plus all the existing rules applied per size.
- **Emitter:** suffixes, 8/32/64-bit register names, `.quad`, `.balign`, `cqo`.
- **Edge cases to test yourself:** `long` parameters beyond the sixth (passed on the stack); a `long` return
  value that is used as an `int`; `static long x = 2147483648;`; comparisons of two `long`s with
  `cmpq`; `-2147483648L` and `9223372036854775807L`.

## Rust focus
- **Exhaustive `match` across many passes.** Adding an assembly type to `Mov` breaks every pattern
  that destructures it. Read each error as a to-do list.
- **`HashMap` as a symbol table.** Read up on the
  [`entry` API](https://doc.rust-lang.org/std/collections/hash_map/enum.Entry.html), and decide whether passes
  receive `&` or `&mut` access to the table.
- **Integer widths.** Store constants as `i64` once they reach the back end, and use
  [`i32::try_from`](https://doc.rust-lang.org/std/primitive.i32.html#impl-TryFrom%3Ci64%3E-for-i32) to test whether an immediate fits.
- **Small `Copy` enums.** An assembly type with no data can derive `Copy`, so you can pass it by value freely.

## Common pitfalls
- Emitting `movslq` with a stack destination, or forgetting to fix up its immediate source.
- Aligning every slot to 4 bytes, so `long`s straddle 8-byte boundaries. The tests may still pass, but the layout is wrong.
- Forgetting that function return values and arguments now have sizes: a `long` returned in `%rax` is read with `movq`, not `movl`.
- Leaving `cdq` before a quadword `idivq`. The result is wrong only for negative or large values, so it is easy to miss.
- Not giving temporaries a type, then guessing their size in codegen.
