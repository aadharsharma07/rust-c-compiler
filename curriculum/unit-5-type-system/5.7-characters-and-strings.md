# Lesson 5.7 — Characters & strings
**Unit:** 5 — A Real Type System · **Type:** Builds `char`, string literals · **Est. time:** 6–8 h · **Tests:** ch. 16
**Prerequisites:** lessons 5.1–5.6

## Learning goals
- Add the three character types `char`, `signed char` and `unsigned char`, and apply the integer promotions to them.
- Lex character constants and string literals with escape sequences.
- Explain the two meanings of a string literal: an array initialiser, or a pointer to read-only static data.
- Emit byte-sized instructions (`movb`, `movsbl`, `movzbl`) and string data (`.ascii`/`.asciz`) for Linux and macOS.
- Call a libc function (`puts`) with a string argument.

## Key ideas
**Three distinct types.** `char`, `signed char` and `unsigned char` are all 1 byte and are three *different* types:
`char *` and `signed char *` are incompatible pointer types. On x86-64 System V, plain `char` is signed, so it behaves
like `signed char` in arithmetic and conversions.

**Integer promotions.** Before any arithmetic, unary operator, or comparison, a character-typed operand is converted to
`int`. So in `c + 1` with `char c`, `c` is sign-extended to `int` first, and the result is `int`. Use the place in your
checker that you found in lesson 5.3. Character *constants* such as `'a'` already have type `int` (value 97).

**Escapes.** Both character constants and string literals understand `\'`, `\"`, `\?`, `\\`, `\a`, `\b`, `\f`, `\n`,
`\r`, `\t`, `\v`. A raw newline inside either is an error, as are an unescaped `'` inside a character constant, an unescaped
`"` inside a string, an empty `''` and an unknown escape. Adjacent string literals concatenate: `"ab" "cd"` is `"abcd"`.

**String literals.** A literal `"hi"` has type `char[3]` (with the terminating NUL). Two cases:
1. It initialises a character array: `char s[4] = "abc";` copies the bytes into `s`. The array may be larger
   (padded with zeros) or *exactly* the length without the NUL (`char s[3] = "abc";` is legal, with no terminator).
   Longer is an error.
2. Anywhere else, it decays like any array, to a pointer to a static, read-only, uniquely labelled constant.

**Worked example.**

```c
int puts(char *s);
int main(void) {
    puts("hi");
    return 0;
}
```

```
tmp.0 = GetAddress(string.0)
tmp.1 = puts(tmp.0)
Return(0)
```

```asm
# Linux                               # macOS
    .section .rodata                      .cstring
.Lstring.0:                           Lstring.0:
    .asciz "hi"                           .asciz "hi"
    .text                                 .text
    ...                                   ...
    leaq  .Lstring.0(%rip), %r11          leaq  Lstring.0(%rip), %r11
    movq  %r11, -8(%rbp)                  movq  %r11, -8(%rbp)
    movq  -8(%rbp), %rdi                  movq  -8(%rbp), %rdi
    call  puts@PLT                        call  _puts
```

`.asciz` appends a NUL; `.ascii` does not (use it for `char s[3] = "abc"` in static storage). In the emitted
assembly, escape `"` and `\`, and write every non-printable byte as a three-digit octal escape such as `\012`.

**Initialising a local `char` array from a string** can write the bytes in chunks. For `char s[4] = "abc";` the bytes are
`61 62 63 00`, which is the little-endian `int` `0x00636261`:

```asm
    movl    $6513249, -4(%rbp)      # "abc\0" in one 4-byte store
```

Use 8-byte chunks while at least 8 bytes remain, then 4, then single bytes. (An 8-byte chunk may need a 64-bit immediate,
which your fix-up pass already handles.)

**Byte-sized code.** Add a `Byte` assembly type: `movb`, and register names `%al`, `%dl`, `%cl`, `%dil`, `%sil`,
`%r8b`, `%r9b`, `%r10b`, `%r11b`. Widening uses `movsbl`/`movsbq` (signed) or `movzbl`/`movzbq` (unsigned), with a register
destination. Narrowing to a byte is a `movb` of the low byte. Conversions between `double` and characters go through `int`:
`cvttsd2sil` then truncate; `movzbl`/`movsbl` then `cvtsi2sdl`.

## Questions the tutor should ask you
1. What is the type of `'a'`? Of `"a"`? What is `sizeof` of each (you will implement `sizeof` in 5.8)?
2. In `char c = 200;`, what value does `c` hold, and what does `c + 0` evaluate to?
3. Why are `char *` and `unsigned char *` incompatible, if both point at single bytes?
4. Which of `char a[3] = "abc";`, `char a[2] = "abc";` and `int a[4] = "abc";` are valid?
5. Why is the bit pattern `0x00636261` the right immediate for `"abc"`?
6. What would go wrong if two identical literals were merged and the program wrote through one of them?

## What you build
- **Lexer:** the `char` keyword; character constants; string literals; escapes as above; reject the malformed cases.
- **Parser:** `char`/`signed char`/`unsigned char` specifiers (reject `signed unsigned char`, `long char`); string literal
  expressions (concatenating adjacent ones).
- **Type checker:** promotions for character operands; string literal typing; array initialisation from a string (any of the
  three character element types is allowed, and a non-character element type is an error); compile-time conversion of
  static initialisers to and from `char` types.
- **Symbol table:** static string constants with a unique name, a value and a "null-terminated" flag.
- **TACKY:** string initialisers lowered to `CopyToOffset` chunks; other string literals become `GetAddress` of a static constant.
- **Assembly/emitter:** the `Byte` type and register names; `Movsx`/`MovZeroExtend` with source and destination types;
  `.byte`, `.ascii`, `.asciz`; the Linux and macOS section directives shown above.
- **Fix-ups:** byte immediates must fit in 8 bits (truncate `movb $256` to `movb $0`); `movsb*`/`movzb*` need a register
  destination and a non-immediate source.
- **Edge cases:** escapes in strings passed to `puts`; arrays of strings `char *names[2] = {"a", "b"};`; `char` parameters
  beyond the sixth; `unsigned char` arithmetic that exceeds 255. Out of scope: arrays declared without a size (`char s[] = "…"`).

## Rust focus
- **Bytes vs. Unicode.** C strings are byte sequences. Store literal contents as `Vec<u8>`, not `String`, and know the
  difference between a Rust [`char`](https://doc.rust-lang.org/std/primitive.char.html) and a `u8`. Byte literals help:

```rust
let newline: u8 = b'\n';
```

- **Little-endian packing.** [`i64::from_le_bytes`](https://doc.rust-lang.org/std/primitive.i64.html#method.from_le_bytes)
  turns 8 bytes into the immediate you need.
- **Formatting escapes.** Implementing the assembly-string escaper is a good small exercise with
  [`std::fmt::Write`](https://doc.rust-lang.org/std/fmt/trait.Write.html).

## Common pitfalls
- Treating plain `char` as unsigned (that is the ARM convention, not x86-64 System V).
- Forgetting promotions, so `c1 + c2` is computed in bytes and overflows.
- Emitting a Rust-escaped string (`{:?}`) into assembly: Rust's `\u{…}` escapes are not valid assembler syntax.
- Putting string constants in `.data`, where they are writable, instead of read-only data.
- Using `.cstring` on macOS for a string that is not NUL-terminated. That section is for C strings only.
