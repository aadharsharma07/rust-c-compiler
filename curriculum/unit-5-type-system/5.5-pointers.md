# Lesson 5.5 — Pointers
**Unit:** 5 — A Real Type System · **Type:** Builds `&`, `*` · **Est. time:** 10–14 h · **Tests:** ch. 14
**Prerequisites:** lessons 5.1–5.4

## Learning goals
- Parse C declarators, which build types "inside out" (`int *f(void)` vs. `int (*p)`), and abstract declarators in casts.
- Represent derived types recursively: a pointer type contains the type it points to.
- Explain *lvalues* vs. *rvalues* and *lvalue conversion*, and lower them to TACKY `GetAddress`, `Load` and `Store`.
- Apply the type rules for pointers: implicit conversions, null pointer constants, comparisons, casts.
- Generate memory operands through a register (`(%rax)`) and addresses with `lea`.

## Key ideas
**Declarators.** In `int *p, x;`, the `*` belongs to `p`, not to the base type. A declaration is a base type
plus a *declarator* that wraps it. Parse the declarator into a small tree (identifier, pointer-to, function-with-params),
then process it: `*D` means "D has type pointer-to-base"; `D(params)` means "D is a function returning base".
Parentheses change the binding: `int *f(void)` is a function returning `int *`; in later lessons `int (*p)[3]` will be a
pointer to an array. Casts use *abstract* declarators with no name: `(int **) x`.

**Lvalues.** An lvalue designates an object: a variable, or `*e` for any pointer `e`. When an lvalue is used as a
value, it undergoes *lvalue conversion*: the object's current contents are read. `&` and the left side of `=` are the
places where an lvalue is *not* converted. `&x` is valid, while `&(x + 1)` and `&3` are errors; `*p = 1` is valid, while `(x + 1) = 1` is not.

**TACKY needs to know whether an expression is a place or a value.** Let expression lowering return one of two results:
a *plain operand* (a value or a variable), or a *dereferenced pointer* (an operand holding an address that has not been
read yet). The caller then decides what to do:
- used as a value: plain → use as is; dereferenced → emit `Load(ptr, tmp)`.
- assigned to: plain → `Copy`; dereferenced → `Store(src, ptr)`.
- address taken: plain → `GetAddress(var, tmp)`; dereferenced → the pointer itself (so `&*p` is just `p`).

**Worked example.**

```c
int main(void) {
    int x = 3;
    int *p = &x;
    *p = 7;
    return x;
}
```

```
x = 3
tmp.0 = GetAddress(x)
p = tmp.0
Store(7, p)
Return(x)
```

```asm
    movl    $3, -4(%rbp)
    leaq    -4(%rbp), %r11        # lea needs a register destination
    movq    %r11, -16(%rbp)       # tmp.0
    movq    -16(%rbp), %r10
    movq    %r10, -24(%rbp)       # p = tmp.0
    movq    -24(%rbp), %rax       # Store: load the pointer…
    movl    $7, (%rax)            # …then write through it
    movl    -4(%rbp), %eax
```

`Load(ptr, dst)` is the mirror image: `movq ptr, %rax` then `movl (%rax), …`. Replace your `Stack(offset)` operand with
a general `Memory(register, offset)` operand; `-4(%rbp)` is simply `Memory(BP, -4)`. A static variable's address is
`leaq x(%rip), %r11` (`_x(%rip)` on macOS).

**Type rules.** A pointer is 8 bytes, uses the `Quadword` assembly type, and compares like an unsigned integer.
- `*e` requires a pointer and has the pointed-to type; `&e` requires an lvalue and has type pointer-to-(type of e).
- *Null pointer constant:* an integer constant expression with value 0 (`0`, `0L`, `0u`). In your subset, a constant literal is enough.
- Conversion "as if by assignment" to a pointer type is allowed from the *same* pointer type or from a null
  pointer constant, and nothing else, so `int *p = 5;` and `long *q = p;` are errors.
- `==`/`!=` need two pointers of the same type, or a pointer and a null constant. The *common pointer type* rule also
  types `c ? p : 0`.
- Explicit casts between pointers and integers are allowed; casts between pointers and `double` are errors.
- Pointer arithmetic and `<`, `>` on pointers come in lesson 5.6. For now, reject `*`, `/`, `%`, unary `-`, `~` on pointers.
- `!p`, `p && q`, `if (p)` are fine: any *scalar* can be tested for truthiness.

## Questions the tutor should ask you
1. Draw the declarator tree for `int *(*x)`. What type does `x` have?
2. In `*p = *q;`, which side is lvalue-converted, and which TACKY instructions result?
3. Why does TACKY generation need two kinds of result, instead of always returning an operand?
4. Is `0L` a null pointer constant? Is `(long) 0`? Is a variable `z` holding 0?
5. Why must `lea` have a register destination, and what does your fix-up do about it?
6. After `int *p = &x;`, can a later pass keep `x` in a register? (This will matter in Units 6–7.)

## What you build
- **Parser:** declarators and abstract declarators for variables, parameters, function return types and casts; `&` and `*`
  as unary operators. Reject declarators that would create function pointers or functions returning functions
  (not supported in this course), e.g. `int (*f)(void);`.
- **Types:** `Pointer(referenced type)`; the type of `&f` for a function is out of scope, so reject taking a function's address.
- **Type checker:** lvalue checks for `&`, `=` and (if you did them) `++`/`--`/compound assignment; dereference checks; the
  conversion rules above; common pointer type for `==`, `!=` and `?:`. Static pointers may be initialised only with a null constant.
- **TACKY:** `GetAddress`, `Load`, `Store`, and the two-variant expression result.
- **Assembly:** `Memory(reg, offset)`; `Lea`; codegen for `Load`/`Store` through `%rax`; pointer comparisons use unsigned condition codes.
- **Fix-ups:** `lea` destination must be a register. Never use `%r10`/`%r11` to hold the pointer for `Load`/`Store`, because
  a later fix-up of the same instruction might overwrite them.
- **Edge cases:** pointers to pointers (`**pp = 1`); `&*p`; a function returning a pointer to a static variable; a
  pointer to `double`; `(int *) 0 == 0`; dereferencing a pointer in a `return`; pointer parameters past the sixth argument.

## Rust focus
- **Recursive types need indirection.** `Pointer` must hold a boxed type. See
  [Box&lt;T&gt; for recursive types](https://doc.rust-lang.org/book/ch15-01-box.html). Make sure equality on
  `Type` still derives cleanly through the `Box`.
- **Returning "one of two things".** The plain-vs-dereferenced result is an enum, not a pair of `Option`s; let `match`
  force every caller to handle both.
- **Avoid clone storms.** Types get compared and copied often. Profile your intuition: is `clone()` on a small boxed tree
  a problem here? (Usually not. Measure before using `Rc`; see [Rc&lt;T&gt;](https://doc.rust-lang.org/book/ch15-04-rc.html).)

## Common pitfalls
- Treating the `*` in `int *p, q;` as part of the base type, so `q` becomes a pointer as well.
- Lvalue-converting the operand of `&` (taking the address of a temporary copy).
- Implementing `*p = v` as `Load` then `Copy` into a temporary, so memory is never written.
- Using signed condition codes for pointer comparisons.
- Changing your null-pointer-constant rule without checking the suite. In full C, `1 - 1` also qualifies; in this
  course's subset only an integer *literal* with value 0 must be accepted. Whatever you choose, record it in your journal.
