# Lesson 5.9 — Structs
**Unit:** 5 — A Real Type System · **Type:** Builds Structs · **Est. time:** 15–25 h · **Tests:** ch. 18
**Prerequisites:** lessons 5.1–5.8 (all of them; this lesson uses every earlier one)

## Learning goals
- Resolve structure tags, which have their own namespace and block scope, and handle incomplete struct types.
- Compute struct layout: member offsets, alignment, padding and total size.
- Type-check and lower member access (`.` and `->`), struct initialisers and whole-struct copies.
- Classify structs into eightbytes (INTEGER / SSE / MEMORY) and pass and return them exactly as System V requires.
- Copy aggregates in the back end without reading or writing past the end of an object.

## Key ideas
**Tags.** `struct point { int x; int y; };` declares a *tag* `point`. Tags live in a separate namespace (a variable may
also be called `point`) and follow block scope. As with variables, give each tag declaration a unique name in your
resolution pass, so that an inner `struct point` that shadows an outer one is a different type. `struct s;` declares an
incomplete type, which you can point to but not use by value until it is defined. A struct may contain a pointer to
itself (`struct node *next;`) but not itself. (In full C, `struct s *p;` with no visible `s` declares one implicitly;
check how the suite treats an unseen tag before you decide.)

**Layout.** Each member goes at the next offset that is a multiple of its alignment. The struct's alignment is the
largest member alignment, and its size is rounded up to a multiple of that alignment:

```c
struct s { char a; int b; double c; char d; };
/* a@0, pad 1–3, b@4, c@8, d@16, pad 17–23 → size 24, alignment 8 */
```

Arrays inside structs use their element alignment. The "16 bytes or more means 16-byte alignment" rule from lesson 5.6 is
for array *variables*, not for array members.

**Member access in TACKY.** Extend the expression result from lesson 5.5 with a third variant: a *sub-object* (a base
variable plus a byte offset). Then:
- `s.m` where `s` is a plain variable → sub-object (`s`, offset of `m`). Reading it is `CopyFromOffset(s, off, dst)`;
  writing it is `CopyToOffset(src, s, off)`.
- `s.m` where `s` is a dereferenced pointer, and `p->m` → add the offset to the pointer (`AddPtr` with scale 1), giving
  a dereferenced pointer to the member.
- Nested access (`a.b.c`) adds offsets together. A whole struct is copied with an ordinary `Copy`; the back end splits it.

**The System V classification** decides how a struct travels in calls.
1. Larger than 16 bytes → **MEMORY**.
2. Otherwise split it into eightbytes (bytes 0–7, 8–15). An eightbyte whose scalar members are *all* `double` is
   **SSE**; any other eightbyte is **INTEGER** (nested structs and array elements are flattened first).

```c
struct a { int x; int y; };          /* [INTEGER]          → %rdi              */
struct b { double d; int i; };       /* [SSE, INTEGER]     → %xmm0 + %rdi      */
struct c { double x; double y; };    /* [SSE, SSE]         → %xmm0 + %xmm1     */
struct d { char c[17]; };            /* MEMORY             → copied onto stack */
```

**Arguments:** each eightbyte takes the next free register of its class. If there are not enough registers left for *all*
of a struct's eightbytes, the *whole* struct goes on the stack, rounded up to a multiple of 8 bytes. **Return values:**
INTEGER eightbytes come back in `%rax` then `%rdx`; SSE eightbytes in `%xmm0` then `%xmm1` (so `[SSE, INTEGER]` returns in
`%xmm0` and `%rax`). For a MEMORY return, the *caller* reserves space and passes its address as a hidden first argument in
`%rdi`, which shifts the visible arguments along by one. The callee writes the result there and returns that same address in `%rax`.

**Worked example.**

```c
struct pair { int a; double b; };    /* size 16, align 8, [INTEGER, SSE] */
double get_b(struct pair p) { return p.b; }
```

```
get_b(p):
    tmp.0 = CopyFromOffset(p, 8)
    Return(tmp.0)
```

```asm
    movq    %rdi, -16(%rbp)       # eightbyte 0: a + 4 bytes of padding
    movsd   %xmm0, -8(%rbp)       # eightbyte 1: b
    movsd   -8(%rbp), %xmm14
    movsd   %xmm14, -24(%rbp)     # tmp.0 = p.b
    movsd   -24(%rbp), %xmm0
```

**Partial eightbytes.** A 12-byte struct's second eightbyte holds only 4 bytes. Moving it with `movq` would read or write
4 bytes past the object, which can corrupt a neighbour or fault at a page boundary. Move exactly the right number of bytes
(for example, a `movl`, or single bytes combined with shifts into one register).

## Questions the tutor should ask you
1. Lay out `struct { char c; double d; char e; }`. What is its size? Can reordering members shrink it?
2. Why does each struct tag declaration need a unique internal name?
3. Classify `struct { long l; double d; }`, `struct { char c; double d; }` and `struct { char c[20]; }`.
4. A function takes six `int`s and then a `struct a`. Where does the struct go, and why?
5. Who allocates the memory for a returned MEMORY-class struct, and how does the callee find it?
6. Why is `f().x = 3;` an error, while `p->x = 3;` is fine?

## What you build
- **Lexer/parser:** the `struct` keyword and `.`/`->` tokens; struct declarations (with or without a member list) at file
  and block scope; struct type specifiers in all declarations, casts and `sizeof`; postfix `.`/`->`; nested initialisers.
- **Resolution:** a tag map with block scoping, parallel to the variable map; unique names for tags.
- **Type table:** for each struct, its size, alignment and ordered members (name, type, offset). Reject duplicate members,
  members of incomplete or `void` type, and redefinition of a tag in the same scope.
- **Type checker:** `.` needs a complete struct, `->` needs a pointer to one; unknown members are errors; struct values may
  be assigned, initialised, passed, returned and used in `?:` only with an *identical* struct type; reject structs in arithmetic,
  comparisons, truthiness tests and casts to struct types; reject declaring an object of incomplete type. `s.m` is an lvalue only if `s` is.
- **TACKY:** `CopyFromOffset`; the sub-object expression result; struct initialisers via `CopyToOffset`; static
  struct initialisers with explicit padding as zero bytes.
- **Assembly:** classification (cache it per struct); argument and parameter passing for every class; return values in
  registers or via the hidden pointer; aggregate copies in 8/4/1-byte chunks.
- **Edge cases:** structs containing arrays and other structs; arrays of structs; pointers to incomplete structs that are
  completed later; structs mixed with scalars beyond six arguments; returning `[SSE, INTEGER]` structs; linking against
  struct-taking functions compiled by the system `cc` (the suite does this). Unions are out of scope.

## Rust focus
- **A type table keyed by tag.** A `HashMap` from unique tag to struct definition; `Type::Structure` holds only the tag.
  If definitions are shared widely, consider [`Rc`](https://doc.rust-lang.org/book/ch15-04-rc.html) rather than cloning.
- **Alignment arithmetic.** [`usize::next_multiple_of`](https://doc.rust-lang.org/std/primitive.usize.html#method.next_multiple_of)
  expresses "round up to alignment" directly:

```rust
assert_eq!(5_usize.next_multiple_of(4), 8);
```

- **Small enums as results.** Classification returns a list of `Integer`/`Sse` eightbytes or `Memory`; an enum makes
  illegal mixes unrepresentable.
- **Split the work.** This lesson touches every module. Commit after each sub-step (layout, member access, copies,
  classification, calls, returns) and run the suite between them.

## Common pitfalls
- Giving a struct the alignment of its *first* member instead of its *largest*.
- Classifying by member types without first flattening nested structs and arrays into eightbytes.
- Splitting a struct between registers and stack when registers run out. It must go entirely on the stack.
- Forgetting that the hidden return pointer occupies `%rdi`, so the first real argument moves to `%rsi`.
- Reading or writing past the end of a struct when copying its last eightbyte.
- Not saving the hidden pointer on entry, then finding `%rdi` clobbered by the time you `return`.
