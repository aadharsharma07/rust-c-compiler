# Lesson 1.2 — Variables and types
**Part:** 1 — Learn Rust · **Unit:** 1 — Rust Basics for Python Programmers · **Type:** Learning · **Est. time:** 3–4 h · **Tests:** none
**Prerequisites:** lesson 1.1

## Overview
This lesson covers how Rust stores values in variables: `let`, immutability by default, `mut`,
shadowing, and the basic **scalar types** (integers, floats, booleans, characters), plus tuples
and arrays. Every one of these is a contrast with Python's "a name can point at anything" model.
Integer sizes in particular matter later: your C compiler has to know that an `int` is 4 bytes
and a `long` is 8, and Rust makes you think in those terms from day one.

## The lesson

### 1. `let` creates a variable, and it's immutable by default
```rust
fn main() {
    let apples = 3;
    println!("I have {} apples", apples);
    // apples = 4;   // error[E0384]: cannot assign twice to immutable variable `apples`
}
```
In Python every name can be reassigned. In Rust, a variable made with plain `let` can't change.
Why? Most variables never need to change, and if the compiler *knows* a value is fixed, you (and
it) can reason about the code more easily: no function call three screens away can have altered
it. When you do need to change it, say so with `mut`:

```rust
let mut score = 0;
score = score + 10;
score += 5;          // compound assignment works like Python
println!("{}", score); // 15
```
Note that Rust has no `++` operator; write `x += 1`.

### 2. Types are fixed: a variable can't change type
```rust
let mut n = 5;
// n = "five";   // error[E0308]: mismatched types: expected integer, found `&str`
```
In Python, `n = 5` then `n = "five"` is fine because names are just labels. In Rust, `n` *is*
a 4-byte slot of memory that holds an integer. It can hold a different integer, never a string.

### 3. Shadowing: a new variable with the same name
You *can* reuse a name by writing `let` again. This creates a brand-new variable that hides
(**shadows**) the old one:
```rust
let input = "42";              // input: &str (text)
let input: i32 = input.parse().unwrap(); // a NEW variable, input: i32
println!("{}", input + 1);     // 43
```
This is not mutation: the first `input` still exists, it's just no longer reachable by name.
Shadowing is handy when you transform a value step by step and don't want names like
`input_str` and `input_num`. (`parse` and `unwrap` are explained in 1.5 and 3.3; here they
turn text into a number, crashing if it isn't one.) Shadowing also respects blocks:

```rust
let x = 1;
{
    let x = x * 10;      // shadows only inside these braces
    println!("{}", x);   // 10
}
println!("{}", x);       // 1
```

### 4. Integer types: you choose the size
Python has one `int` type with unlimited size: `2 ** 100` just works. Real CPUs don't work that
way. They operate on fixed-size chunks: 8, 16, 32 or 64 **bits** (a bit is a 0 or 1; 8 bits make
a **byte**). Rust exposes this directly:

| Type | Size | Range |
|---|---|---|
| `i8` / `u8` | 1 byte | −128..127 / 0..255 |
| `i16` / `u16` | 2 bytes | −32,768..32,767 / 0..65,535 |
| `i32` / `u32` | 4 bytes | about ±2.1 billion / 0..about 4.3 billion |
| `i64` / `u64` | 8 bytes | about ±9.2×10¹⁸ / 0..about 1.8×10¹⁹ |
| `isize` / `usize` | pointer-sized (8 bytes on a 64-bit machine) | used for sizes and indexes |

`i` means **signed** (can be negative), `u` means **unsigned** (zero or positive only). If you
don't say, an integer literal defaults to `i32`. You'll meet `usize` constantly: lengths and
indexes into lists are always `usize`, because a length can't be negative.

**Overflow.** Since sizes are fixed, a value can be too big. `let x: u8 = 256;` is a compile
error. If arithmetic goes out of range *at run time*, a debug build **panics** (stops the
program with an error message), while a release build silently wraps around (255 + 1 becomes 0).
If you want wrapping on purpose, say so: `x.wrapping_add(1)`; to detect it, `x.checked_add(1)`.
You'll study how this works in binary in lesson 6.1.

Literals can include underscores for readability and a type suffix: `1_000_000`, `255u8`,
`0xff` (hex), `0b1010` (binary).

### 5. Floats, booleans and characters
- **Floats**: `f64` (8 bytes, the default, the same as Python's `float`) and `f32` (4 bytes).
  `let pi = 3.14159;` is an `f64`.
- **Booleans**: `bool`, values `true` and `false` (lowercase, unlike Python's `True`/`False`).
  Operators are `&&` (and), `||` (or), `!` (not), instead of Python's `and`, `or`, `not`.
- **Characters**: `char`, written with **single** quotes: `'a'`, `'é'`, `'🦀'`. A `char` is one
  Unicode character, always 4 bytes. Double quotes make a string (`"a"`), a different type.
  Python has no separate character type: `"a"` is just a length-1 `str`.

### 6. No silent conversions
Python happily mixes `int` and `float` (`1 + 2.5` gives `3.5`). Rust refuses to mix types, even
two integer types:
```rust
let a: i32 = 10;
let b: i64 = 20;
// let c = a + b;          // error[E0308]: mismatched types: expected `i32`, found `i64`
let c = a as i64 + b;      // explicit conversion with `as`
let avg = 7 as f64 / 2.0;  // 3.5
```
`as` converts between numeric types. Be careful: `as` can lose information (`300 as u8` is `44`,
`3.9 as i32` is `3`). Being forced to write the conversion makes the cost visible. This is the
first of many places where Rust prefers explicit over convenient.

### 7. Type annotations and inference
You can always write the type with `: Type`, and sometimes you must:
```rust
let x = 5;          // inferred i32
let y: u64 = 5;     // annotated: now 5 is a u64
let z = 5u64;       // same thing, via a suffix
let guess: u32 = "17".parse().unwrap(); // annotation tells parse what to produce
```
Rust infers types from how values are *used*, within a function. When it can't figure it out, it
asks: `error[E0282]: type annotations needed`. Python type hints are optional documentation; Rust
annotations are part of the program and checked every time.

### 8. Compound types: tuples and arrays
A **tuple** groups a fixed number of values, possibly of different types (like a Python tuple,
but the types are fixed):
```rust
let point: (i32, i32, f64) = (3, -4, 5.0);
let (x, y, dist) = point;          // destructuring, like Python unpacking
println!("{} {} {}", x, point.1, dist);  // access by .0, .1, .2
```
An **array** has a fixed length and one element type. It cannot grow (for growable lists you'll
use `Vec` in 3.4):
```rust
let primes: [i32; 5] = [2, 3, 5, 7, 11];   // [type; length]
let zeros = [0u8; 4];                     // [0, 0, 0, 0]
println!("{} {}", primes[0], primes.len());
// primes[10]  -> panics at run time: index out of bounds
```
Indexing past the end panics, like Python's `IndexError`, rather than reading random memory
(which is what C would do, as you'll see in Part 3).

### 9. Printing for debugging
`{}` uses a type's user-facing format. Tuples and arrays don't have one, so use `{:?}`, the
**debug** format: `println!("{:?}", primes);` prints `[2, 3, 5, 7, 11]`. You can also put
variable names inside the braces: `println!("{x} and {y:?}");`. The `dbg!(expr)` macro prints
the file, line, expression and value, which is great for quick debugging.

2. Write a shadowing chain: start with a `&str` like `"  128  "`, shadow it with a trimmed
   version (`.trim()`), then with a parsed `u8`, then with that number doubled as a `u16`.
   Print each step with `{:?}`.
3. Print the minimum and maximum of `i8`, `u8`, `i32`, `u64` using `i8::MIN`, `i8::MAX`, etc.
   Compare each to the table above.
4. Overflow experiment: first write `let x: u8 = 255;` and add 1 with `+`. The compiler may
   spot the overflow itself and refuse to compile ("this arithmetic operation will overflow"):
   read that error. To get a *run-time* overflow, hide the value from the compiler by parsing
   it: `let x: u8 = "255".parse().unwrap();`. Add 1 and run with `cargo run` (debug), then with
   `cargo run --release`. Write down both outcomes. Then try `checked_add` and `wrapping_add`
   and print their results with `{:?}`.

## Common pitfalls
- **Single vs. double quotes.** `'a'` is a `char`; `"a"` is a string. They don't mix.
- **Using `mut` when shadowing was meant** (or the reverse). Changing the *type* needs `let`.
- **Assuming `as` is safe.** It silently truncates or wraps; use it deliberately.
- **Writing `True`, `and`, `not`.** Rust uses `true`, `&&`, `!`.
- **Forgetting `{:?}`** for tuples and arrays: `{}` gives "doesn't implement `Display`".
