# Lesson 1.4 — Control flow
**Part:** 1 — Learn Rust · **Unit:** 1 — Rust Basics for Python Programmers · **Type:** Learning · **Est. time:** 2–3 h · **Tests:** none
**Prerequisites:** lessons 1.1–1.3

## Overview
This lesson covers how Rust makes decisions and repeats work: `if` (which is an expression),
the three loops `loop`, `while` and `for`, ranges, and a first look at `match`, Rust's powerful
pattern-matching construct. `match` in particular will be everywhere in your compiler: every
pass looks at a node, matches on what kind it is, and does something different for each kind.

## The lesson

### 1. `if` / `else if` / `else`
```rust
let temp = 23;
if temp > 30 {
    println!("hot");
} else if temp > 15 {
    println!("pleasant");
} else {
    println!("cold");
}
```
Differences from Python: no colon, braces are required (even for one line), `else if` instead of
`elif`, and parentheses around the condition are not needed (the compiler warns if you add them).

**The condition must be a `bool`.** Python treats `0`, `""` and `[]` as false ("truthiness").
Rust doesn't:
```rust
let count = 3;
// if count { ... }       // error[E0308]: expected `bool`, found integer
if count != 0 { println!("non-zero"); }
```
This removes a class of bugs where an empty value is accidentally treated as false. You say
exactly what you mean.

### 2. `if` is an expression
Because `if` is an expression (recall 1.3), it produces a value. This replaces Python's
conditional expression `a if cond else b`:
```rust
let n = -7;
let sign = if n < 0 { "negative" } else { "non-negative" };
```
Both branches must have the **same type**, because `sign` can only have one type:
```rust
// let x = if n < 0 { 1 } else { "one" };  // error[E0308]: `if` and `else` have incompatible types
```
An `if` used as a value must have an `else`; otherwise, what would the value be when the
condition is false?

### 3. `loop`: repeat forever (until `break`)
```rust
let mut tries = 0;
loop {
    tries += 1;
    if tries == 3 {
        break;
    }
}
```
`loop` is Rust's `while True:`. It exists separately because the compiler then knows the body
runs at least once and only exits via `break`. A `loop` can even return a value through `break`:
```rust
let mut n = 1;
let first_big_power = loop {
    n *= 2;
    if n > 1000 {
        break n;           // the loop's value
    }
};                         // first_big_power == 1024
```
`continue` skips to the next iteration, as in Python.

### 4. `while`: repeat while a condition holds
```rust
let mut countdown = 3;
while countdown > 0 {
    println!("{}", countdown);
    countdown -= 1;
}
println!("liftoff");
```
Same as Python's `while`, with the same `bool`-only rule for the condition.

### 5. `for` and ranges
Rust's `for` works like Python's: it loops over the items of something iterable.
```rust
for i in 0..5 {           // 0, 1, 2, 3, 4  (like Python's range(5))
    println!("{}", i);
}
for i in 1..=5 { }        // 1..=5 includes 5: 1, 2, 3, 4, 5
for i in (0..10).step_by(3) { }  // 0, 3, 6, 9  (like range(0, 10, 3))
for i in (1..4).rev() { }        // 3, 2, 1     (like reversed(range(1, 4)))
```
`a..b` is a **range**: start included, end excluded (Python's `range(a, b)`). `a..=b` includes
the end. Looping over an array:
```rust
let primes = [2, 3, 5, 7];
for p in primes {
    println!("{}", p);
}
for (i, p) in primes.iter().enumerate() {   // like Python's enumerate()
    println!("{}: {}", i, p);
}
```
Prefer `for` over manually indexing with `while i < len`: it can't go out of bounds, and it's
clearer. (`.iter()` and friends get a full lesson in 4.3.)

### 6. Loop labels
To break out of an outer loop from an inner one, label it with `'name:`:
```rust
'outer: for row in 0..10 {
    for col in 0..10 {
        if row * col > 20 {
            break 'outer;    // leaves both loops
        }
    }
}
```
Python has no equivalent (you'd use a flag or a function with `return`).

### 7. A first look at `match`
`match` compares a value against a series of **patterns** and runs the code of the first one
that fits. Python 3.10 added a similar `match` statement, but in Rust it's an expression and it's
used constantly.
```rust
let code = 404;
let message = match code {
    200 => "OK",
    301 | 302 => "redirect",          // | means "or"
    400..=499 => "client error",      // an inclusive range pattern
    500..=599 => "server error",
    _ => "unknown",                   // _ matches anything: the catch-all
};
```
Each line is an **arm**: `pattern => expression,`. Three rules:
1. Arms are tried top to bottom; the first match wins.
2. Like `if`, every arm must produce the same type, since the `match` has one value.
3. **`match` must be exhaustive**: every possible value must be covered by some arm. Delete the
   `_` arm above and you get `error[E0004]: non-exhaustive patterns: i32::MIN..=199_i32 ...
   not covered`. The compiler has checked every possible `i32` for you.

Exhaustiveness is why `match` is so valuable in a compiler: when you later add a new kind of
C expression, the compiler points out every `match` that doesn't handle it yet. You'll see
`match` at its full strength with enums in 3.2.

An arm's body can be a block for multi-line work:
```rust
match n % 3 {
    0 => println!("fizz-ish"),
    remainder => {                       // a name binds the value
        println!("remainder {}", remainder);
    }
}
```
A plain name like `remainder` is a pattern that matches anything and gives it that name.

### 8. Putting it together: a worked trace
```rust
let mut total = 0;
for n in 1..=6 {
    let kind = if n % 2 == 0 { "even" } else { "odd" };
    match kind {
        "even" => total += n,
        _ => continue,
    }
}
// total == 2 + 4 + 6 == 12
```
Trace it: `n = 1` is odd, so `continue`; `n = 2` is even, so `total = 2`; and so on to 12.

   `"positive"`, using `if` as an expression. (`&'static str` is the type of a string literal

   (if even, halve it; if odd, 3n + 1).
6. With nested `for` loops and a loop label, find the first pair `(a, b)` with `1 <= a, b <= 20`

## Check your understanding
1. Why does Rust reject `if count { ... }` when `count` is an integer? What Python behaviour does that rule out?
2. Why must both branches of an `if` used as a value have the same type, and why must there be an `else`?
3. When would you choose `loop`, `while` or `for`?
4. What's the difference between `0..5` and `0..=5`?
5. What does "`match` must be exhaustive" mean, and why is it useful when code changes later?

## Common pitfalls
- **Relying on truthiness.** Write the comparison: `!= 0`, `.is_empty()`.
- **Off-by-one ranges.** `1..10` stops at 9. Use `..=` when you mean "up to and including".
- **Forgetting the comma** between `match` arms, or the `;` after `let x = match ... { };`.
- **Overusing `_`.** A catch-all silences exhaustiveness checking; use it only when you really mean "everything else".
- **Indexing in a `while` loop** when a `for` over the collection would do.
