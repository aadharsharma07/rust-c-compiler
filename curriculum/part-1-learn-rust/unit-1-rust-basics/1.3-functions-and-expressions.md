# Lesson 1.3 — Functions and expressions
**Part:** 1 — Learn Rust · **Unit:** 1 — Rust Basics for Python Programmers · **Type:** Learning · **Est. time:** 2–3 h · **Tests:** none
**Prerequisites:** lessons 1.1–1.2

## Overview
You'll learn to define functions with typed parameters and return values, and meet one of
Rust's most important ideas: almost everything is an **expression** that produces a value,
including blocks `{ ... }`. This changes how you write code compared with Python, where most
lines are statements. It's also directly relevant to compilers: the C language you'll compile
separates *statements* from *expressions*, and you'll model that distinction in your AST.

## The lesson

### 1. Defining functions
```rust
fn greet() {
    println!("hello");
}

fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    greet();
    let total = add(2, 3);
    println!("{}", total); // 5
}
```
Compared with Python's `def add(a, b): return a + b`:
- `fn` instead of `def`, braces instead of a colon and indentation.
- **Every parameter must have a type.** Rust never infers parameter types. A function's
  signature is a contract the compiler checks at every call site, so `add(2, "x")` fails to
  compile wherever it appears.
- **The return type** comes after `->`. No arrow means the function returns nothing useful.
- Functions can be defined in any order; `main` can call a function defined below it.
- Names are `snake_case`, as in Python. The compiler warns if you use `camelCase`.

### 2. Statements vs. expressions
This is the key idea of the lesson.
- An **expression** is a piece of code that *evaluates to a value*: `5`, `a + b`, `add(1, 2)`,
  `x > 3`.
- A **statement** is an instruction that *does something* but has no value: `let x = 5;` is a
  statement.

Python blurs this a little, but you know the difference: you can write `y = (x + 1)` but not
`y = (z = 3)` (in Python, `=` is a statement; that's why the walrus operator `:=` was added).

In Rust, the semicolon is the switch:
- `a + b` is an expression with a value.
- `a + b;` (with a semicolon) is an **expression statement**: evaluate it, then throw the
  value away.

### 3. The last expression is the return value
A function body is a block, and **a block's value is its final expression, if it has no
semicolon**. That's why `add` above has no `return`:
```rust
fn square(n: i64) -> i64 {
    n * n        // no semicolon: this value is returned
}
```
Add a semicolon by mistake and you get a classic error:
```rust
fn square(n: i64) -> i64 {
    n * n;
}
```
```
error[E0308]: mismatched types
 --> src/main.rs:1:22
  |
1 | fn square(n: i64) -> i64 {
  |    ------            ^^^ expected `i64`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
2 |     n * n;
  |          - help: remove this semicolon to return this value
```
`()` is the **unit type**: the type of "no meaningful value", written as an empty tuple. It's
roughly Python's `None` as a return value. A function with no `->` returns `()`. Here the body
ended with a statement, so its value was `()`, not `i64`.

`return` still exists, for leaving a function early:
```rust
fn safe_div(a: i32, b: i32) -> i32 {
    if b == 0 {
        return 0;     // early exit
    }
    a / b             // normal result: tail expression
}
```
Idiomatic Rust uses `return` only for early exits and lets the tail expression do the rest.

### 4. Blocks are expressions too
Any `{ ... }` block has a value, so you can use one wherever a value is expected:
```rust
let area = {
    let width = 3;
    let height = 4;
    width * height      // the block's value
};                      // note the semicolon: this ends the `let` statement
println!("{}", area);   // 12; width and height no longer exist here
```
This is useful for computing a value with some temporary variables that shouldn't leak into the
rest of the function. Python has nothing like it; you'd use a helper function or let temporaries
leak. In the next lesson you'll see that `if` and `match` are expressions too, which replaces
Python's `x if cond else y`.

### 5. A worked example, step by step
```rust
fn describe(n: i32) -> i32 {
    let doubled = n * 2;          // statement: binds doubled
    let adjusted = {              // statement whose right side is a block expression
        let bonus = 1;
        doubled + bonus           // block value
    };
    adjusted * 10                 // tail expression = return value
}
```
Calling `describe(4)`: `doubled = 8`; the block computes `8 + 1 = 9`, so `adjusted = 9`; the
tail expression gives `90`, which is returned. Trace it this way, labelling each line
"statement" or "expression", until it feels natural.

### 6. Parameters are copies (for now)
For the number types you've met, passing a value to a function copies it, much like passing an
`int` in Python. Changing the parameter (if declared `mut`) doesn't change the caller's variable:
```rust
fn bump(mut x: i32) -> i32 {
    x += 1;
    x
}
let a = 5;
let b = bump(a);   // a is still 5, b is 6
```
For heap-allocated values like strings, passing works differently: ownership *moves* into the
function. That's the whole of Unit 2; for now, stick to numbers, `bool` and `char`.

### 7. Returning several values
Return a tuple, just as you would in Python:
```rust
fn min_max(a: i32, b: i32) -> (i32, i32) {
    if a < b { (a, b) } else { (b, a) }
}
let (lo, hi) = min_max(9, 2);
```

### 8. Comments and doc comments
`//` starts a line comment (Python's `#`). `/* ... */` is a block comment. `///` is a **doc
comment** placed above a function; `cargo doc` turns it into documentation, like a docstring:
```rust
/// Returns the larger of two numbers.
fn bigger(a: i32, b: i32) -> i32 { if a > b { a } else { b } }
```

## Build
Create `cargo new functions-lab`. Write each function, call it from `main`, and print results.
1. `celsius_to_fahrenheit` taking and returning `f64` (F = C × 9/5 + 32). Check that 100 °C gives 212.
2. Add a semicolon after the tail expression of that function on purpose. Read the error and
   find the `help:` line. Explain `()` in your notes.

4. `abs_diff` taking two `i32`s and returning their absolute difference as a `u32`, using an
   early `return` for one case and a tail expression for the other.
5. In `main`, compute a value using a block expression containing at least two temporary
   variables. After the block, try to print one of the temporaries and read the error.
6. Write a function that returns a tuple `(quotient, remainder)` of two `u32`s (use `/` and `%`).
   Destructure the result in `main`.

   the wrong type. Record the error codes.
8. Add a `///` doc comment to each function and run `cargo doc --open` to see them rendered.

## Common pitfalls
- **The stray semicolon** on the tail expression (`expected i32, found ()`).
- **The missing semicolon** after `let x = { ... };`: the `let` statement needs it.
- **Writing `return x` at the end of every function.** It works, but isn't idiomatic.
- **Expecting a function to change the caller's number.** Numbers are copied in.
