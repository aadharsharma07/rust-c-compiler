# Lesson 2.6 — Comparisons & Control Flow
**Unit:** 2 — Expressions and an IR · **Type:** Builds relational + logical ops · **Est. time:** 6–8 h · **Tests:** ch. 4
**Prerequisites:** lessons 2.4, 2.5

## Learning goals
- Explain how `cmp` sets the CPU flags and how `setcc` and `jcc` read them.
- Lower relational operators (`==` `!=` `<` `<=` `>` `>=`) and `!` to `cmp` + `setcc`, producing exactly 0 or 1.
- Implement short-circuit evaluation of `&&` and `||` with labels and conditional jumps in TACKY.
- Generate unique labels and emit them with the right local-label prefix per platform.
- Handle 1-byte register names and the `cmp` operand constraints in the emitter and fix-up pass.

## Key ideas
**Flags.** `cmpl b, a` (AT&T order!) computes `a - b`, throws the result away and sets flags
(zero, sign, overflow, carry). A following `setCC dst` writes 1 to a **byte** operand if
condition `CC` holds, else 0; `jCC label` jumps if it holds. Signed conditions:

| C | `cmp b, a` then… | CC |
|---|---|---|
| `a == b` | `sete` / `je` | `E` |
| `a != b` | `setne` / `jne` | `NE` |
| `a < b` | `setl` / `jl` | `L` |
| `a <= b` | `setle` / `jle` | `LE` |
| `a > b` | `setg` / `jg` | `G` |
| `a >= b` | `setge` / `jge` | `GE` |

`setcc` writes only 1 byte, so zero the full 4-byte destination first with `movl $0, dst` (`mov`
doesn't touch flags, so it may sit between `cmp` and `setcc`; `xor` would clobber them).

**New tokens and precedence:** `!`, `&&`, `||`, `==`, `!=`, `<`, `>`, `<=`, `>=`. Longest match
matters again (`<=` vs `<`, `!=` vs `!`). `!` is a unary operator. Binary precedences:
`<` `<=` `>` `>=` 35, `==` `!=` 30, `&&` 10, `||` 5 (all left-associative).

**TACKY additions.** `Not` unary operator; relational binary operators; and plain control flow:
```
Copy(val src, val dst) | Jump(identifier target)
JumpIfZero(val condition, identifier target) | JumpIfNotZero(val condition, identifier target)
Label(identifier)
```
**Short-circuiting.** In `a && b`, `b` must not be evaluated if `a` is 0 (it might divide by zero).
So `&&` can't be a `Binary` instruction; it becomes branches:
```
<instructions for e1>              # v1 = result
JumpIfZero(v1, and_false.0)
<instructions for e2>              # v2 = result
JumpIfZero(v2, and_false.0)
Copy(1, result)
Jump(and_end.1)
Label(and_false.0)
Copy(0, result)
Label(and_end.1)
```
`||` mirrors it with `JumpIfNotZero` and the constants swapped. Labels need unique names, from a
counter like temporaries (a `.` in the name keeps them distinct from C identifiers).

**Lowering to assembly** (new instructions: `Cmp(op, op)`, `Jmp(label)`, `JmpCC(cc, label)`,
`SetCC(cc, op)`, `Label(id)`):

| TACKY | Assembly AST |
|---|---|
| `Binary(LessThan, a, b, dst)` | `Cmp(b, a)`, `Mov(Imm 0, dst)`, `SetCC(L, dst)` |
| `Unary(Not, src, dst)` | `Cmp(Imm 0, src)`, `Mov(Imm 0, dst)`, `SetCC(E, dst)` |
| `JumpIfZero(v, t)` | `Cmp(Imm 0, v)`, `JmpCC(E, t)` |
| `Copy(s, d)` | `Mov(s, d)` |

**`cmp` fix-ups:** both operands in memory → source via `%r10d`; second operand an immediate
(e.g. `cmpl $0, $1`) → move it into `%r11d` first.

**Worked example.** `return 2 < 3;` → TACKY `tmp.0 = 2 < 3`, `Return(tmp.0)` → fixed-up body:
```
	movl	$2, %r11d
	cmpl	$3, %r11d
	movl	$0, -4(%rbp)
	setl	-4(%rbp)
	movl	-4(%rbp), %eax
```
**Emission details.** Local labels: `.Land_false.0` on Linux, `Land_false.0` on macOS (labels
are not C symbols, so no `_`). `JmpCC(E, x)` → `je .Lx`; `SetCC(cc, Reg)` uses byte registers
`%al`, `%dl`, `%r10b`, `%r11b`; a `Stack` operand stays `n(%rbp)` (setcc writes one byte there).

## Questions the tutor should ask you
- In `cmpl $3, %r11d`, which value is subtracted from which? Which `setcc` gives `2 < 3`?
- Why must `Mov(Imm 0, dst)` come before `SetCC`, and why is it allowed to sit after `Cmp`?
- Why can't `&&` be a TACKY `Binary` instruction like `+`?
- What does `!5` evaluate to, and what instruction sequence produces it?
- Why must label names be unique across the whole program, not just within one expression?

## What you build
- **Lexer/parser:** the nine new tokens; `!` in the factor parser; the new binary operators in the
  precedence table. Rejects e.g. `return 1 < ;`, `return !;`, `return 1 =< 2;`.
- **TACKY:** the new instructions and operators; short-circuit translation for `&&`/`||`; a
  unique-label generator sharing state with the temporary generator.
- **Assembly AST + lowering:** `Cmp`, `Jmp`, `JmpCC`, `SetCC`, `Label`, a condition-code enum.
- **Passes:** pseudo replacement visits `Cmp` and `SetCC` operands; fix-up handles both `cmp` rules.
- **Emitter:** platform local-label prefix; 1-byte register names for `setcc`; `jmp`, `jCC`, labels on their own line.
- **Unit tests:** TACKY for `1 && 0`, `0 || 2`, `!(1 < 2)`; emitted assembly for `2 < 3`.

A plain function can take the size as a parameter rather than overloading `Display`; e.g. a
`fn reg_name(r: Reg, bytes: u8) -> &'static str` signature is a legitimate design choice.

## Common pitfalls
- Swapping `cmp` operands, which silently inverts `<` and `>`.
- Using `setl %eax` (it needs a byte register: `%al`) or skipping the zeroing `mov`.
- Evaluating both sides of `&&`/`||` eagerly; tests with side effects in later chapters will catch it.
- Emitting labels with a `_` prefix or without `.L`/`L`, so they become (possibly duplicate) global symbols.
- Lexing `<=` as `<` then `=`.
