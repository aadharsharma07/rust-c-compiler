# Lesson 2.1 — Unary Operators
**Unit:** 2 — Expressions and an IR · **Type:** Builds unary `-`, `~` · **Est. time:** 2–3 h · **Tests:** ch. 2 (`--stage lex`, then `--stage parse`)
**Prerequisites:** lessons 1.1–1.6 (chapter 1 passing)

## Learning goals
- Extend a grammar with a recursive rule and update lexer, AST and parser consistently.
- Explain why `--` must be lexed as its own token even though `rcc` doesn't support decrement.
- Know what negation (two's complement) and bitwise complement do to a 32-bit integer.
- Use `Box` to build a recursive enum and practise following compiler errors after adding a variant.

## Key ideas
**New tokens:** `-` (hyphen), `~` (tilde), and `--` (decrement). By longest match, `--2` lexes as
`--` followed by `2`, not as two minus signs. C defines `--` as the decrement operator, which
needs an lvalue (a variable); `--2` is therefore a *syntax-level* error in our compiler. Lexing
`--` as a single token means the parser rejects it naturally, because no grammar rule accepts it.
`- -2` (with a space) and `-(-2)` are fine: both are negation of negation.

**Grammar:**
```
<exp>   ::= <int> | <unop> <exp> | "(" <exp> ")"
<unop>  ::= "-" | "~"
```
The rule `<unop> <exp>` refers to `<exp>` itself, so the parser function for expressions calls
itself. Parentheses only group: they never appear in the AST.

**AST:**
```
exp            = Constant(int) | Unary(unary_operator, exp)
unary_operator = Complement | Negate
```
Because `Unary` contains an `exp`, the Rust type is recursive and needs indirection (a `Box`).

**Worked example.** `return ~(-2);`
- Tokens: `Return Tilde OpenParen Hyphen Constant(2) CloseParen Semicolon`
- AST: `Return(Unary(Complement, Unary(Negate, Constant(2))))`
- Meaning: `-2` is `0xFFFFFFFE`; `~` flips every bit, giving `0x00000001` = `1`. In two's complement,
  `~x == -x - 1` for every `int` `x`.

**Choosing a branch.** The expression parser peeks at the next token: a constant → `Constant`;
`-` or `~` → consume it and parse an operand; `(` → consume, parse an expression, expect `)`;
anything else → error. This "peek and dispatch" is the core of recursive descent.

## Questions the tutor should ask you
- Why is `--2` invalid but `-(-2)` valid? Which stage rejects it, and why that stage?
- What would happen to `a--b` (in a later chapter) if your lexer only knew `-`?
- Why does a recursive enum need `Box`? What is the size of a type that contains itself directly?
- Your parser sees `(`. What does it do, and what node does it return for `(2)`?
- What is `~0`? What is `-(-2147483647)`? Why does the test suite avoid `-(-2147483648)`?

## What you build
- **Lexer:** add `Hyphen`, `Tilde` and `Decrement` tokens. `--` must win over `-` by longest match.
- **AST:** extend the expression enum with a unary variant holding an operator and a boxed
  operand; add the unary-operator enum.
- **Parser:** implement the new `<exp>` rule with peek-and-dispatch, including parenthesised
  expressions. Errors: `--` anywhere in an expression, missing operand (`return -;`), unbalanced
  parentheses, operator after operand (`return 2-;` is still invalid in chapter 2, since binary
  operators don't exist yet).
- **Codegen:** your assembly generator from Unit 1 can't handle `Unary` yet. Make it return a
  clear "not implemented" error (or `todo!()`) for now; lessons 2.2–2.3 replace it.
- **Unit tests:** token streams for `-`, `~`, `--`; ASTs for `~(-2)`, `-(-2)`, `-~2`, `((5))`;
  rejection of `--2`.

In Rust, bitwise complement is spelled `!` on integers, not `~`: `!0i32 == -1`. Useful for writing test expectations.

## Common pitfalls
- Lexing `--` as two `-` tokens, so `--2` is wrongly accepted.
- Representing parentheses as an AST node.
- Writing `Unary(op, Exp)` without a `Box` and getting "recursive type has infinite size".
- Adding a catch-all `_ =>` arm somewhere and silently mishandling the new variant.
- Breaking chapter 1: re-run `--chapter 1` after every change.
