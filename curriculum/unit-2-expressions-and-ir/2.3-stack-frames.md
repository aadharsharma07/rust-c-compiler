# Lesson 2.3 — Stack Frames
**Unit:** 2 — Expressions and an IR · **Type:** Builds pseudoregister + fix-up passes · **Est. time:** 5–8 h · **Tests:** ch. 2
**Prerequisites:** lessons 1.5, 1.6, 2.2

## Learning goals
- Explain the stack, `%rsp` and `%rbp`, and what a function prologue and epilogue do.
- Lower TACKY to assembly using *pseudoregisters*, then replace each one with a stack slot.
- Recognise x86-64 operand constraints (no memory-to-memory `mov`) and fix them in a separate pass.
- Structure the back end as a sequence of small passes over a mutable instruction list.
- Use a `HashMap` to assign each pseudoregister a unique offset.

## Key ideas
**The stack.** The stack grows *down* (towards lower addresses). `%rsp` points at the top (the
lowest in-use address). On entry to a function, a *prologue* saves the caller's frame pointer and
establishes a new frame:
```
	pushq	%rbp          # save caller's frame pointer
	movq	%rsp, %rbp    # rbp = base of our frame
	subq	$8, %rsp      # reserve 8 bytes for locals/temporaries
```
Locals live at negative offsets from `%rbp`: `-4(%rbp)`, `-8(%rbp)`, …. The *epilogue* undoes
it before every `ret`:
```
	movq	%rbp, %rsp    # discard the frame
	popq	%rbp          # restore caller's frame pointer
	ret
```
(These are 64-bit `q` instructions because addresses are 64 bits.)

**Pseudoregisters.** TACKY has unlimited temporaries; the machine has 16 registers. The simplest
correct strategy: first lower each `Var("tmp.n")` to an abstract `Pseudo("tmp.n")` operand, then
give each distinct pseudo its own 4-byte stack slot. (Unit 7 replaces this with real register
allocation.) Splitting it into two passes keeps instruction selection ignorant of memory layout.

**Extended assembly AST:**
```
instruction    = Mov(operand src, operand dst) | Unary(unary_operator, operand)
               | AllocateStack(int) | Ret
unary_operator = Neg | Not
operand        = Imm(int) | Reg(reg) | Pseudo(identifier) | Stack(int)
reg            = AX | R10
```
`negl` negates its operand in place; `notl` flips its bits in place. So TACKY
`Unary(op, src, dst)` lowers to `Mov(src, dst)` then `Unary(op, dst)`; `Return(val)` lowers to
`Mov(val, Reg(AX))`, `Ret`.

**Fix-up.** `mov` (like most x86-64 instructions) can't have *both* operands in memory. After
pseudo replacement, `movl -4(%rbp), -8(%rbp)` is illegal; rewrite it through the scratch register
`%r10d`: `movl -4(%rbp), %r10d` then `movl %r10d, -8(%rbp)`. The fix-up pass also inserts
`AllocateStack(n)` at the start of the function, where `n` is the total stack bytes used.

**Worked example.** `return ~(-2);`, TACKY from lesson 2.2:
```
# after instruction selection        # after pseudos → stack       # after fix-up (emitted)
Mov(Imm 2, Pseudo tmp.0)             movl $2, -4(%rbp)              pushq %rbp
Unary(Neg, Pseudo tmp.0)             negl -4(%rbp)                  movq %rsp, %rbp
Mov(Pseudo tmp.0, Pseudo tmp.1)      movl -4(%rbp), -8(%rbp)  ✗     subq $8, %rsp
Unary(Not, Pseudo tmp.1)             notl -8(%rbp)                  movl $2, -4(%rbp)
Mov(Pseudo tmp.1, Reg AX)            movl -8(%rbp), %eax            negl -4(%rbp)
Ret                                  ret                            movl -4(%rbp), %r10d
                                                                    movl %r10d, -8(%rbp)
                                                                    notl -8(%rbp)
                                                                    movl -8(%rbp), %eax
                                                                    movq %rbp, %rsp
                                                                    popq %rbp
                                                                    ret
```
(Plus `.globl _main` / `_main:` on macOS.) The program exits with `1`.

**Where the prologue and epilogue come from.** Emit the prologue as part of a function's header,
and make `Ret` *emit* the three-line epilogue. `AllocateStack(n)` emits `subq $n, %rsp`.

## Questions the tutor should ask you
- Why does the stack slot for the first temporary live at `-4(%rbp)` and not `0(%rbp)`? What is at `0(%rbp)`?
- What would go wrong if you forgot the epilogue but kept the prologue?
- Why separate "replace pseudos" from "fix up instructions"? What would merging them cost?
- Your pseudo-replacement pass sees `tmp.0` twice. How does it know to reuse the same slot?
- Why is `%r10d` safe to use as scratch here? When might a scratch register become unsafe?

## What you build
- **Assembly AST:** extend it as above (replacing Unit 1's dataless `Register` with `Reg(reg)`).
- **TACKY → assembly pass:** lowers `Return` and `Unary` using pseudos. Chapter 1 programs now go
  through TACKY too; delete the old AST→asm path.
- **Pseudo-replacement pass:** walks every instruction, replacing each `Pseudo(name)` with
  `Stack(offset)`, giving new names the next slot (`-4`, `-8`, …) via a name → offset map, and
  returning the total bytes allocated.
- **Fix-up pass:** inserts `AllocateStack(bytes)` first; rewrites any `Mov` whose source and
  destination are both `Stack` into two moves via `R10`.
- **Emitter:** prologue after the label; `Ret` → epilogue; `Stack(n)` → `n(%rbp)`; `Reg(AX)` → `%eax`,
  `Reg(R10)` → `%r10d`; `Unary(Neg, x)` → `negl x`, `Unary(Not, x)` → `notl x`.
- **Driver:** `--codegen` now stops after the fix-up pass.
- **Unit tests:** pseudo replacement for the worked example yields the middle column; fix-up yields
  the right column (minus prologue/epilogue, which come from emission).

## Common pitfalls
- Assigning a fresh slot every time a pseudo appears instead of once per name.
- Using `movl` in the prologue/epilogue (they move 64-bit addresses: `pushq`, `movq`, `popq`).
- Emitting `ret` without the epilogue, which returns to garbage because `%rsp` is wrong.
- Allocating the stack in the instruction-selection pass, before you know how many slots exist.
- Getting the offset sign wrong (`4(%rbp)` overwrites the saved `%rbp` that `popq` restores later).
