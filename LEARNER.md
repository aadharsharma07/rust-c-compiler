# Learner profile

Every tutor reads this before teaching. Pitch every lesson at this level.

| | |
|---|---|
| **Languages** | Python: comfortable writing real code. No other languages. |
| **Rust** | None. Starting from zero. |
| **Low-level knowledge** | Conceptual and rusty: knows the words (stack, heap, pointer, register, assembly), but not how they really work. |
| **Compilers** | No formal background. |
| **Preferred style** | **Explain, then build.** Teach the full concept first, with examples. Then I build. Questions come at the end, to check understanding. |
| **Course order** | 1) Learn Rust → 2) Learn compiler concepts → 3) Build the compiler in Rust. |

## What this means for teaching
- **Never assume C knowledge.** C syntax, pointers and undefined behaviour need explaining when they first appear.
- **Bridge from Python.** Explain new Rust ideas by contrast: "in Python you'd write…; in Rust…, because…". Do the same for memory: Python's reference-counted, garbage-collected objects vs. Rust's ownership.
- **Explain before asking.** Never open a lesson with questions. Teach first, let me build, then check.
- **Make low-level ideas concrete.** Use diagrams of memory and the stack, and step through examples instruction by instruction.
